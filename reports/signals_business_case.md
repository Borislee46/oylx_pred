# Signals: 让每一次选校建议都有6万个案例做支撑

> 给业务和CEO讲清楚：这系统干什么、为什么不调ChatGPT、凭什么比别人强

---

## 一、今天的问题

一个学生走进XDF，说"我想去香港读金融硕士"。

顾问脑子里开始搜索：去年好像有个差不多背景的学生，申港大金融录了？还是被拒了？GPA多少来着？哦不对，那是前年申新加坡那个……

最后顾问说："你这个条件，应该没问题。"

**这不是顾问的问题，是人的问题。** 没有人能记住6万个案例。没有人能同时比较1000个专业。没有人能完全不受今天心情、上一个学生结果、最近某个极端案例的影响。

于是出现三个问题：

| 问题 | 后果 |
|------|------|
| **判断不一致** | 同一个学生问两个顾问，得到两个答案 |
| **覆盖面窄** | 顾问只推荐自己熟悉的学校和专业，学生错过可能更适合的机会 |
| **经验流失** | 资深顾问离职，十年积累的案例判断也随之离开 |

---

## 二、我们做了什么

一个简单的逻辑：**与其让每个顾问凭记忆判断，不如让系统帮他们查6万个历史案例。**

学生填表（GPA、本科学校、想申的学校和专业、语言成绩……）→ 系统立刻扫描全部历史记录 → 找到背景最相似的一批案例 → 告诉你：这些人里，录取了多少个。

然后更进一步——不只给一个数字，还告诉你为什么是这个数字：

> *"你的GPA比同类申请者低，这个因素拖低了8%。但你最大的问题是跨专业——数学本科转金融，相关性不够，这个因素拖低了35%。语言成绩没问题。"*

学生和顾问就知道了：**GPA不用再刷了，重点是想办法补专业匹配度。**

## 三、一个真实的例子

**背景**：211院校数学系，GPA 3.1，IELTS 6.5，想申香港大学金融硕士。

**传统顾问**："港大金融很难，你这个条件有点悬。要不看看城大？"

学生会想：是真的悬，还是顾问懒得帮我看？

**用Signals之后**：

系统遍历了覆盖范围内的23所院校×1051个专业，返回每个组合的概率。发现：
- 港大金融：18%（冲刺）——确实难，主要卡在跨专业
- 港大统计：42%（匹配）——数学底子在，相关性高
- 港中文金融：35%（匹配）——同一专业方向但竞争略缓
- 城大金融：52%（保底）

学生说："那我申港大统计和港中文金融，两所都冲一下。城大金融保底。"

**顾问不再是"我说你行你就行"的裁判，而是"数据在这，我们一起看"的向导。**

## 四、为什么不直接问ChatGPT

这个问题每次都会被问到。我们用最简单的方式回答。

**问ChatGPT"我能申上港大金融吗"，它会怎么做？**

它不会去查数据（它也没数据可查）。它根据自己读过的网页和文章，编一段听起来合理的回答："港大金融竞争激烈，GPA 3.1有一定难度，但你的数学背景是个优势，建议……"

听起来很专业对吧？但问题是：

**你明天再问一次，它可能给你完全不同的回答。**

因为ChatGPT不是在算概率，是在写作文。它不知道港大金融去年录了几个数学系的学生。它的"70%录取概率"不是算出来的，是凭空写的。

更关键的是——**学生的GPA、本科院校、语言成绩，全都发到了OpenAI的服务器上。**

| | 问ChatGPT | 用Signals |
|---|---|---|
| **回答靠什么** | 靠语言能力编 | 靠6万个真实案例算 |
| **问三次答案一样吗** | 大概率不一样 | 100%一样 |
| **数据去哪了** | 发到美国服务器 | 留在公司内网 |
| **能解释为什么吗** | 事后编理由 | 每一步可追溯 |
| **每次花多少钱** | 几毛到几块 | 几乎为零 |

**一句话：ChatGPT是聊天工具，不是决策工具。聊天可以靠语言能力，决策必须靠数据。**

## 五、市面上的留学AI产品，和我们的区别

现在留学赛道做AI的不少。大致分两类：

### 第一类：ChatGPT套壳

产品形态：用户填个表 → 拼一段Prompt发给ChatGPT → 把返回结果包装一下展示。

**问题在哪？** 它没有自己的数据。ChatGPT不知道港大某专业的录取率，能给的建议全是泛泛的"提升GPA""丰富软背景"。用户花了钱，得到的其实是任何人在ChatGPT里免费能问到的东西。

**我们的区别**：我们不做套壳。我们有6万条XDF内部案例，这是任何通用AI都没有的。

### 第二类：传统中介经验派

做法：让最资深的顾问带新人，靠传帮带积累判断力。

**问题在哪？** 一个顾问再资深，脑子里也就几百个案例。而且人走了经验就没了。

**我们的区别**：系统不离职。每多一条新案例，系统就聪明一点点。

### 我们的护城河

| 壁垒 | 为什么别人不好追 |
|------|------------------|
| **6万条真实案例** | XDF十多年积累，不是公开数据，也不是能爬到的 |
| **领域规则** | 不只是看数字，还懂跨专业、跨学科、语言门槛这些留学特有的逻辑 |
| **跑在一台小服务器上** | 不需要GPU/不需要买API/不需要云服务，一台4核2G的机器一天处理几万次查询 |
| **一个人开发维护** | 不需要团队。改规则、加学校、调逻辑都是一个人搞定 |

## 六、对业务意味着什么

### 直接收益

| 指标 | 以前 | 现在 |
|------|------|------|
| 选校效率 | 顾问手动翻案例，一个学生30-60分钟 | 输入背景即出结果，几秒钟 |
| 覆盖面 | 顾问推荐自己熟悉的几十个项目 | 系统遍历1000+专业，不遗漏 |
| 新人上手 | 跟老顾问学半年到一年 | 系统辅助下，新人第一周就能给数据驱动的建议 |
| 知识沉淀 | 在顾问脑子里，离职即流失 | 在系统里，每新增一个案例都在自动积累 |
| 客户信任 | "顾问说的" | "数据说的"，可信度更高 |

### 隐性收益

**标准化**：不管哪个校区的顾问，给同一个学生同一个建议。品牌体验一致。

**数据资产**：每一条预测记录、每一个最终录取结果，都在喂养系统。用得越久，系统越准。这是**数据飞轮**——竞争对手追不上的不是技术，是时间。

**风险控制**：顾问给的建议是可追溯的。万一出现纠纷（"你们当初说我能申上的！"），系统有完整的决策记录。

## 七、能做什么，不能做什么

不讲局限性的系统介绍是不完整的。以下如实说明。

### 系统能做什么

| 场景 | 系统表现 |
|------|---------|
| 学生背景和申请目标都在历史数据覆盖范围内 | 给出量化概率 + 逐因素归因，可追溯每一步 |
| 学生没想好去哪 | 遍历23校×1051专业，按概率排序，不做遗漏 |
| 学生想知道该提升什么 | 逐层分解每个因素的影响，优先补短板 |
| 顾问需要给客户一个可信的参考 | 数据驱动的判断，比"我觉得"更有说服力 |
| 日常大批量选校咨询 | 几秒钟出结果，几乎零成本 |

### 系统不能做什么

**1. 冷门组合——历史上没人申请过**

一个冷门双非院校的冷门专业学生，想申一个极少有人申过的目标专业。

系统里可能只有0-2个类似案例。这时候给出的概率本质上不是"预测"，而是"基于最相似案例的粗略估计"。系统会在结果上标注"数据稀疏，仅供参考"。

**怎么办**：这种情况没有技术能解决——没有数据就是没有数据。我们的做法是**诚实告知**。与其给一个看起来精确但实际是瞎猜的数字，不如告诉顾问和学生："这个组合历史上样本太少，无法给出可靠估计。建议作为冲刺尝试，不要押注。"

**2. 全新学校或全新专业**

某大学新开了一个专业，第一年招生，零历史案例。

系统无法给出数据驱动的预测——因为没有数据。只能基于该学校类似专业、或该专业在其他学校的情况做类比估计，准确性大打折扣。

**怎么办**：对于新项目，系统会明确标注"无历史数据，基于相似项目估计"。顾问需要结合自己的行业判断——这个学校新开的专业，第一年通常会降低门槛还是提高门槛？这是人的判断力发挥作用的时刻。

**3. 极端背景的学生**

GPA 4.0、IELTS 9.0、3篇SCI论文——或者反过来，GPA 2.0、无语言成绩、无实习。

系统在极端值上的预测最不可靠，因为训练数据里几乎没有这样的案例。

**怎么办**：对于极端高分学生，系统的预测偏保守（实际录取率可能比系统给的更高）。对于极端低分学生，系统已经给出了地板概率（0.5%），但不会直接输出0——"没有绝对不可能"。顾问需要据此管理客户预期。

**4. 外部环境变化**

签证政策突然收紧、某校扩招200人、新双边协议签署——这些系统都不知道。

系统用的是历史数据，反映的是过去的录取模式。如果录取环境发生了结构性变化，系统会滞后一到两个申请季才能反映。

**怎么办**：这是数据系统的固有限制。短期靠顾问的行业敏感度（政策变化、院校动态），长期靠新数据进来后系统自动更新。

### 坦诚的意义

上面这些"不能"，不是一个系统有缺陷的标志。恰恰相反——**知道什么情况下不该信任系统，才是真正理解了这个系统。**

我们的原则是：**能算的给出数字，算不了的告诉用户"这个我不确定"。** 不确定本身是有价值的信息——它告诉顾问和学生"这条路确实没人走过，你得自己判断"。

## 八、下一步

系统现在能做的事：输入背景 → 输出概率 + 解释原因。

下一步最关键的事只有一件：**闭环**。

顾问标记每个预测的最终结果（录了/拒了/没申）→ 系统每月自动对账 → 发现偏差自动告警。

这件事的成本几乎为零（加一个标记字段），但收益巨大——我们从此知道模型在真实用户身上到底准不准，而不是只在历史数据上自测。
