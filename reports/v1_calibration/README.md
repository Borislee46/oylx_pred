# V1: 校准深度分析

## 关键发现

### 概率校准本身几乎是完美的

| 指标 | 校准前 (Raw XGBoost) | 校准后 (Sigmoid) |
|------|---------------------|-------------------|
| 平均预测概率 | 0.3953 | 0.3429 |
| 实际录取率 | 0.3374 | 0.3374 |
| 偏差 | +5.79pp | +0.55pp |
| Brier Score | 0.2044 | 0.1859 |
| Calibration (可靠性) | 0.0202 | **0.0011** |
| Refinement (区分度) | 0.0394 | 0.0388 |
| Uncertainty (不可约) | 0.2236 | 0.2236 |
| ECE | 0.1179 | **0.0263** |

### "高估 21%"的真相

评估 JSON 里有一条：`positive_rate_predicted=54.9% vs actual=33.7%`。

这**不是**概率校准问题 — 这是 **threshold 问题**。

- 校准后平均预测概率 = 0.3429，实际录取率 = 0.3374 → 偏差不到 1pp
- 但在 threshold=0.24 下，55% 的 case 被标记为"正例" → 产生 21pp 的"表面高估"
- threshold=0.24 是 F1 最优解，故意偏召回方向（宁可多推，不少漏）

**面试叙事**：
> "很多人看一眼 54.9% vs 33.7% 就下结论说模型高估。我做了校准分析后，发现概率本身几乎完美校准（bias < 1pp），'高估'来自 F1 最优 threshold=0.24 把大量中等概率 case 划为正例。这是 recall-favor 的设计选择，不是 bug。"

## DS 批判反思 (2026-05-13)

这份报告的核心结论——"校准后概率几乎完美"——有一个致命盲区：它测的是 **Platt scaling 之后、调整链之前** 的 ECE。2026-05 全链路诊断发现，5 层调整链把 ECE 从 0.026 打到了 0.1155。所以 V1 测的不是用户看到的概率的校准——是中间态的校准。这个教训很重要：**以后测校准必须测全链路，不能只测 base model**。

不过 V1 的另一个洞察仍然成立且重要："高估 21% 是 threshold 问题不是校准问题"。这个区分在面试中很有价值——低阶 DS 会直接说"模型高估"，高阶 DS 会追问"是概率不准还是阈值设错了"。

**Platt scaling 压缩概率范围的局限性**：校准后概率被压缩到 [0.14, 0.73]，这被描述为"符合教育场景直觉"。但 Platt scaling 的概率压缩是 sigmoid 函数的数学性质，不是业务设计。极端 case（GPA<1.5 + 无语言成绩 + 双非申 top 院校）理论上概率应接近 0%——当前模型强制给 0.14 的下限，不是因为业务上"没有绝对不可能"，而是因为 Platt scaling 压缩了尾部分布。这是一个 model artifact，不是 domain insight。需要在 tail calibration 上单独验证。

## 通用 Caveat：无 True Held-Out Set

**所有 V 系列报告（V1-V9）均在 cases.feather 的 train/test split 上评估。** 该 split 与训练数据来自同一个数据生成过程（XDF 内部签约咨询学生，2015-2025），不是真正的 held-out set。

- ECE/AUC/Kendall τ 等指标代表模型在**训练分布**上的表现
- 不代表模型在**新用户、新时间窗口、新地区**上的表现
- 外部验证只有 V6 的 ApplySquare/Compass 定性分析——V6 已证明外部校准严重恶化（-67pp ApplySquare、-5pp Compass）
- 唯一的 true held-out validation 是上线后的用户反馈——当前没有系统化的生产环境 A/B 或监控

这是项目当前最大的方法论盲区，面试中应主动承认而非回避。
