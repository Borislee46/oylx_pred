# Signals: 留学录取概率预测系统 — 技术架构与深度说明

> **目标读者**：CEO、数据科学家、技术面试官
> **前置阅读**：`signals_business_case.md`（业务价值与竞争力）
> **目的**：阐明系统的技术架构、数据全链路、设计决策的trade-off、以及对局限性的诚实评估

---

## 一、系统架构总览

### 1.1 技术栈

| 组件 | 技术选型 | 理由 |
|------|---------|------|
| 推理引擎 | XGBoost 3.0.2 (375 trees, depth=10) | monotonic constraints保证GPA/语言单调性 |
| 概率校准 | Platt Scaling (sigmoid), 2参数 | 仅2参数，强制平滑单调，避免isotonic在小样本bin上的非单调 |
| 后处理 | 6层领域规则链 + 衰减仲裁器 | 弥补ML在稀疏区域的外推不可靠 |
| LLM集成 | DeepSeek, 7个Agent | 不做预测，只做解读/提取/盲评 |
| 文本信号 | TF-IDF + Ridge回归 | 轻量可解释，均值提升0.36%，ΔECE≈0 |
| 前端 | Streamlit | Python原生，单人可维护 |
| 部署 | 单Pod 4核2GB, 80端口 | 无GPU/无分布式/无外部API依赖 |
| 数据存储 | .feather格式 + st.cache_data | 无数据库依赖 |

### 1.2 架构原则

```
离线：XGBoost训练 + Platt校准 → .ubj模型文件
在线：表单输入 → 特征工程 → XGBoost推理 → 6层调整链 → LLM解读 → 输出
```

- **无状态**：session_state为唯一状态载体，无数据库
- **单一真相源**：`config/` 目录为所有配置的单一来源
- **可审计**：每条预测有完整的Adjustment Trace
- **资源最小化**：单人可维护，不需要GPU集群、K8s、微服务

## 二、数据全链路

从原始输入到最终概率，数据经过9个变换步骤。每一步引入假设和偏差。

### 2.1 链路全景

```
表单输入（GPA、语言、院校、专业、经历文本）
    │
    ▼
[1] 特征工程 → XGBoost推理 → Platt Scaling校准
    │  问题：99.4%的特征组合在训练集中≤4个样本，模型在绝大多数输入上执行外推
    │
    ▼
[2] GPA惩罚 — penalty = min(0.8, 0.15 × z²)，z = (μ_gpa − gpa) / σ_gpa
    │  假设：GPA低于均值时，录取概率呈二次函数下降
    │  设计决策：DEC-002（二次优于线性/阈值）
    │
    ▼
[3] 语言惩罚 — 五级阶梯函数，惩罚幅度0.2至0.95
    │  假设：语言成绩具有门槛效应，低于某阈值时概率断崖式下降
    │  设计决策：阶梯函数捕捉IELTS/TOEFL的离散门槛特征
    │
    ▼
[4] 跨专业惩罚 — 乘数范围0.5~1.0，按major相似度线性插值
    │  假设：相似度<0.89即触发惩罚
    │  问题：0.89阈值来自历史实验，相似度<0.80区间几乎无样本（dead zone）
    │
    ▼
[5] 跨学部惩罚 — 硬编码学部转移矩阵，跨学部×0.3
    │  假设：理学部→人文学部几乎不可行，理学部→工学部基本无障碍
    │  设计决策：DEC-005（学部转移规则）
    │
    ▼
[6] 职业学位惩罚 — MBA等专业学位，无实习经历×0.7
    │  假设：专业学位预设工作经验要求
    │
    ▼
[7] 仲裁器 — 衰减因子0.85ⁿ⁻¹，总惩罚上限70%
    │  问题：各层独立设计，但5层叠加后的联合效应从未被系统设计
    │  设计决策：DEC-007（事后补救，非事前设计）
    │
    ▼
[8] TF-IDF文本提升 — 经历关键词匹配 → 概率提升0~15%
    │  均值提升0.36%，ΔECE≈0，对排序有实质影响但校准影响可忽略
    │
    ▼
[9] 归一化 — floor 0.005 → 最终概率区间 [0.005, 0.72]
```

### 2.2 关键数据事实

| 事实 | 含义 |
|------|------|
| 61,716行，52,327个唯一组合 | 平均每个组合1.18个样本 |
| 99.4%的组合≤4个样本 | 模型在几乎所有输入上都是外推，不是内插 |
| 仅1个组合有30+样本 | 不存在统计显著的个案预测 |
| 训练集ECE=0.1155，偏差-9pp | 内部都偏，外部更偏 |
| 外部ApplySquare偏差-67pp | 相似度匹配差异放大惩罚效应7倍 |
| 模型从未输出>0.72 | 仲裁器70%上限+floor效应 |
| ≈6%输入完全预测失败 | 无GPA+冷门本科→冷启动 |

## 三、调整链设计逻辑与批判

### 3.1 各层设计依据

6层惩罚各自有独立的设计决策记录（DECISIONS.md），每层对应真实的领域知识。

| 层级 | 领域逻辑 | 为何不由ML自行学习 |
|------|---------|-------------------|
| GPA惩罚 | GPA低于均值时，边际影响非线性递增 | 训练数据中GPA极端值样本极少，ML在稀疏区域外推不可靠 |
| 语言惩罚 | IELTS 6.0与5.5的差距显著大于7.0与6.5的差距 | ML习得的语言特征权重为全局线性，无法捕捉阶梯效应 |
| 跨专业惩罚 | 数学→金融与数学→文学的逻辑距离完全不同 | ML仅将专业编码为类别变量，不理解语义相似度 |
| 跨学部惩罚 | 理工科转人文几乎不可行，属于领域硬约束 | 样本量不足以让ML从数据中习得此类稀疏模式 |
| 职业学位惩罚 | MBA、MPH等专业学位预设工作经验要求 | 训练数据中申请此类专业的学生基本具备实习经历，缺乏反例 |
| 仲裁器 | 防止5层惩罚叠加后对多短板学生惩罚过度 | DEC-007事后引入，0.85衰减系数来自校准实验 |

### 3.2 批判性评估

> 6层惩罚各自有独立的设计决策记录，但**联合效应从未被系统设计过**。每一层的设计者在问"这个因素需要修正吗"，但没有人在加了5层之后问"这些修正加在一起还是合理的吗？"

核心发现：
- **ECE = 0.1155**（>0.10视为严重失校准），系统性低估约9个百分点
- **分层偏差不均**：C9院校背景学生被低估18pp，双非院校背景学生仅被低估6pp——惩罚机制对强背景申请者的伤害不成比例地更大
- **外部验证**：ApplySquare数据集偏差-67pp，当相似度匹配质量下降时，更多惩罚层被触发，偏差呈指数级放大
- **TODO-1实验（2026-05-13）**：Faculty 3-tier + per-layer ceiling + sim threshold调整后，ECE仅降0.002（0.1155→0.1135），偏差仅改善1pp（-9→-8pp）——边际收益递减，已进入over-engineering区间

核心Trade-off：领域规则确保预测在常识范围内（不会给GPA=2.0的申请者输出90%概率），但代价是系统性低估，尤其对强背景申请者。

### 3.3 设计哲学

当前调整链是**逐层追加**（additive layering）的产物，而非**联合设计**（joint design）的产物。每层单独看都有道理——这是"local rationality"。但在5层叠加后，联合效应超出了任何单一设计者的预期——这是"global irrationality"。

这种模式在工业级ML系统中非常典型：每个修正解决一个真实问题，但没有人在每次追加后重新问"整个系统现在在做什么"。意识到这个问题本身，比证明自己正确更重要。

## 四、ML与LLM的分工：深层逻辑

### 4.1 任务分类矩阵

| 任务类型 | 技术选型 | 核心需求 | LLM能否胜任 |
|----------|---------|---------|------------|
| 录取概率预测 | XGBoost + Platt校准 | 校准概率、确定性、可复现 | 否——LLM输出文本，非概率 |
| 院校专业排序 | XGBoost + 调整链 | 一致排序、不受prompt波动影响 | 否——排序随采样变化 |
| 结果解读 | LLM (DeepSeek) | 自然语言生成 | 是——这是LLM的核心能力 |
| 背景信息提取 | LLM (DeepSeek) | 从自由文本结构化提取 | 是——信息抽取是LLM强项 |
| 独立盲评 | LLM (DeepSeek) | 模拟招生官独立评估 | 部分——Pearson r=0.44，排序一致性偏弱 |

### 4.2 范畴错误（Category Error）

若让LLM直接输出录取概率：LLM没有能力基于61,716条数据做统计推理，它的"70%"是对训练语料中类似表述的模仿，不是计算。

将LLM用于概率预测，是混淆了"生成一段关于概率的文本"和"计算一个概率值"。前者是语言能力，后者是统计能力。两者在输出形式上可能相似（都是一个百分比数字），但产生机制完全不同。

### 4.3 正确的混用模式

```
ML边界：数值推理、概率估计、排序、阈值决策
    ↕ 接口：Adjustment Trace（结构化数据）
LLM边界：自然语言生成、信息抽取、定性评估
```

ML与LLM之间通过结构化数据（Adjustment Trace）通信，而非自然语言。这保证了信息传递的保真度——LLM解读的是已经计算好的数值，而不是自己去生成数值。

## 五、系统能做什么，不能做什么

一个宣称"准确率98%"的系统比一个声明"ECE=0.1155"的系统危险得多。诚实是数据科学专业性的基准。

### 5.1 系统能做什么

| 能力边界 | 说明 |
|----------|------|
| 主流院校+主流专业的概率估计 | 数据覆盖密集区域，模型输出+调整链给出可追溯的量化概率 |
| 全量组合排序 | 23校×1051专业全遍历，不遗漏非热门选项 |
| 逐因素归因 | 6层调整链每层独立输出，每个因素的影响可量化、可质疑 |
| 确定性输出 | 同一输入严格同一输出，不受时间/并发/心情影响 |
| 极低推理成本 | 单次预测≈0.0001元，日处理量无硬性上限 |

### 5.2 数据稀疏：最根本的结构性限制

| 统计量 | 数值 | 含义 |
|--------|------|------|
| 总案例数 | 61,716 | — |
| 唯一组合数 | 52,327 | (院校×专业×本科院校×本科专业) |
| 每组合平均样本数 | 1.18 | 绝大部分组合仅1个样本 |
| 样本≤4的组合占比 | 99.4% | 模型在几乎所有输入上执行外推，不是内插 |
| 样本≥30的组合数 | 1 | 不存在统计显著的个案预测 |

这不是调参或特征工程能解决的结构性问题。当某个组合历史上只有0-2个样本时，系统给出的不是"预测"，而是"基于最相似案例的粗略估计"。

**当前对策**：
- 系统对稀疏组合标注"数据稀疏，仅供参考"，而非假装精确
- 相似度回退机制：当精确匹配无数据时，回退到相似专业/院校的案例
- 约6%的输入完全无法预测（无GPA+冷门本科+冷门目标），系统明确告知而非强行输出

**根本解法**：积累更多数据。这是唯一真正的解法。

### 5.3 校准偏差

- ECE（Expected Calibration Error）= 0.1155，超过0.10的可靠性阈值
- 系统性低估约9个百分点：模型输出的概率普遍低于实际录取率
- 分层偏差不均：C9学生被低估18pp，双非学生被低估6pp
- 输出上限0.72：仲裁器70%上限+floor效应共同作用，模型从不输出高置信度预测

**根因**：6层调整链逐层追加（additive layering），每层独立设计，联合效应从未被系统设计过。每层单独看都有道理（local rationality），5层叠加后联合效应超出预期（global irrationality）。

**当前对策**：DEC-007衰减仲裁（0.85ⁿ⁻¹，总惩罚上限70%），是事后补救而非事前设计。TODO-1实验尝试调优Faculty 3-tier + per-layer ceiling + sim threshold，ECE仅降0.002——已进入边际收益递减区间。

**根本解法**：新数据进来后重新校准。调整链参数需要在更大的、有时序标签的数据集上做联合优化，而非逐层调参。

### 5.4 评估的局限性

- 当前评估基于训练数据的random split，无法反映模型在真实未来数据上的表现
- 外部验证数据集（ApplySquare 507条、Compass 17K条）与训练集分布存在差异，偏差方向已知但量级存疑
- **模型在真实新用户上的预测质量未知**——这是系统中最大的认知缺口

**对策**：部署闭环反馈系统（见第六节P0），顾问标记每条预测的实际结果，每月自动更新校准指标。这是ROI最高的改进——成本极低，收益是结束"不知道模型在真实用户上表现如何"的状态。

### 5.5 选择性标签（Selective Labels）

训练数据仅包含"学生提交了申请→录取/拒了"的结果。缺失的反事实数据：学生想申请但被顾问劝阻的组合、自认为无望未尝试的组合、系统预测低概率后顾问不再推荐的组合。

**潜在后果**：系统预测某组合概率低→顾问不推荐→学生不申请→该组合永无新训练数据→模型对该组合的低概率预测"自我实现"。这一反馈循环目前未被监控。

**对策**：探索性推荐（Exploration Arm，见第六节P1）。5%的推荐有意包含模型不看好的组合，主动收集反事实数据，打破自我强化循环。

### 5.6 冷启动与极端案例

**新专业/新院校**：零历史案例，只能基于相似项目类比估计。准确性无法验证。

**极端背景学生**：GPA≥3.95、IELTS 9.0、多篇论文等超高配置，或反向的极端低配。训练数据中几乎不存在这类案例，模型完全在外推。

**外部环境变化**：签证政策、院校扩招、双边协议等结构性变化，系统需要1-2个申请季的数据才能反映。

**对策**：
- 冷启动：相似度启发式估计 + 明确标注"无历史数据，基于相似项目类比"
- 极端案例：高分者系统偏保守（实际概率可能更高），低分者给出地板概率0.005但不输出0——"没有绝对不可能"
- 环境变化：短期依赖顾问行业判断，长期随新数据自动校准

### 5.7 其他已知限制

- **无时间维度**：训练数据缺少可靠时间戳，无法区分2023与2025的录取标准变化。S1滚动回测未检测到明显漂移，但random split下这符合预期——真正的漂移只会在未来数据中出现
- **地域限定**：仅覆盖港澳新马硕士项目，不可外推
- **语言特征信息损失**：TOEFL与IELTS合并为单一特征，V4 bootstrap显示该特征方差最高（std=0.63），合并可能丢弃有用信号

## 六、资源约束下的优先级判断

以下展示的是在资源约束条件下，对"什么该做、什么不该做"的判断逻辑。

### 应优先执行

**P0：闭环反馈系统**
- 内容：顾问标记每条预测的实际结果（录取/拒录/未申请），系统每月自动更新ECE和校准曲线，偏差超阈值时告警
- 成本：极低，增加一个标记字段
- 理由：ROI最高的改进——以最小成本结束"模型在真实用户上表现未知"的状态

**P1：探索性推荐（Exploration Arm）**
- 内容：5%的推荐结果有意包含模型不看好的组合，收集反事实数据，打破选择性标签的反馈循环
- 成本：低，需业务方伦理审批
- 理由：防止模型持续自我强化偏差，是长期可持续性的基础

**P2：时序切分评估**
- 内容：获取时间戳后，按时间维度划分训练/测试集
- 成本：需数据治理配合
- 理由：random split在时序数据上过于乐观，时序切分给出更真实的held-out估计

### 不应执行

- **升级GPU或换用深度学习模型**：在99.4%组合≤4个样本的前提下，更多参数只会更过拟合
- **增加特征维度**：当前10个特征已覆盖主要信号源，额外特征在现有数据规模下更可能是噪声
- **拆分微服务**：单Pod满足当前全部需求，引入分布式架构增加运维复杂度而不带来业务收益

## 七、总结

从技术视角看，本项目的核心价值不在于模型创新，而在于三项工程判断力：

1. **知道什么时候不用LLM** — 概率预测属于ML，自然语言生成属于LLM。在当前AI行业普遍"用LLM解决一切"的氛围下，能清晰划分边界本身就是竞争力
2. **知道什么时候不信任ML** — ML在稀疏区域的外推不可靠，需要领域规则兜底。但坦承领域规则的联合效应未被系统设计过，ECE=0.1155，系统性低估~9pp
3. **知道在资源约束下不做什么** — 不上GPU、不加特征、不拆微服务。判断什么不该做，比判断什么该做更需要工程成熟度
