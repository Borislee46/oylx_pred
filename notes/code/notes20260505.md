# 项目审视：从面试官视角看 oylx_pred

> 2026-05-05 | 核心问题：这个项目离"让大厂 DS 一面挺直腰板"还差什么

---

## 1. 入口文件的叙事错位

**现状**：`main.py` 读起来像一个"内部 SaaS 工具的入口"——OAuth 回调、维护模式、权限分级、按钮 grid。面试官第一眼看到的标签是"业务系统工程师"，不是"做模型的人"。

**真正值钱的部分**（全被埋在两层目录之下）：
- XGBoost monotonic constraints + sigmoid calibration
- 5 层概率调整链
- 6 个 Agent 的 orchestrator

**建议**：不修改 `main.py`（公司内部继续用），另起一个面向外部的入口：
- `examples/predict_one_case.py` 或 `notebooks/01_pipeline_walkthrough.ipynb`
- 30 行代码：学生背景 dict → 最终概率，打印每层 trace
- 配校准曲线 + 调整链可视化（SVG/mermaid）
- README 第一屏放这两张图

---

## 2. Agent 系统应升格为第三叙事

**当前判断**：用户把项目最大亮点定位为"5 层调整链 + 概率校准"。

**问题**：`src/agent/` 的价值被低估了——

| 已具备的能力 | 面试价值 |
|---|---|
| 6 个 Agent 在生产环境运行 | 绝大多数候选人聊 Agent 是聊概念 |
| 自建 context + registry + orchestrator | 你有线上 audit history |
| 三级 JSON 修复链路 | 超时降级、缓存穿透等真实踩坑细节 |
| Lead-in Agent 帮顾问填表 | Explain Agent 解释结果 |

**建议**：升格为第三个独立叙事——**"Agent 编排：从 LLM API 到生产可用 Pipeline"**。2026 年 DS 岗都在抢"既懂 ML 又能把 LLM 跑稳"的人。

**当前缺口**：`ds-one-year-todo.md` 里没有 Agent 相关博客计划；简历里 Agent 是"附属功能"。

---

## 3. Selective Labels / Self-Fulfilling Prophecy（关键短板）

**背景**：`ds-qa-session-20260503.md` Q2 的回答被 reviewer 指出"绕开了真正的难点"。

**具体方案**：在 pipeline 中加一个轻量 exploration arm：
- 每个学生的 top-K 推荐里，强制保留 1 个系统打分偏低（5%-15%）的"挑战档"
- 标注为探索性建议
- 持续记录这部分推荐的实际申请率和录取率
- 一个申请季后就有第一份 holdback evaluation 数据

**工程量**：2-3 天

**面试回报**：不是一行简历字，而是一个完整故事——"我做了一个会自我校准、并且能识别自己 feedback loop 风险的决策系统"。这是二三面 leader 关的杀手级素材。

## 4. Demo 升级：从给数字到给故事

**当前 todo（Q1.5）**：Streamlit Cloud 免费部署脱敏 demo。

**升级版本**：demo 里加"查看每次预测的概率调整链 trace"按钮，每层 before/after 实时展示。

- 普通 demo：给一个数字
- 你的 demo：给一个故事
- 面试官可以输入极端 case 自己玩 2 分钟
- 技术上就是把已有的 `_adjustment_trace` 渲染出来，工程量极小，杠杆极大

## 5. 元层面：面试驱动的迭代节奏

**当前 todo 的问题**：排得太线性——Q1 作品建设 → Q2 AB 理论 → Q3 ML 深度 → Q4 开始投递。

**核心矛盾**：一次面试经历的 calibration 信号比 3 周看 Kohavi 强 10 倍。

**建议**：
- 现在就投 1-2 家中型互联网（哈啰、得物、小红书）练手，不为 offer，为面经
- 项目改进方向应该被面试反馈驱动，而不是被"理想清单"驱动
- `ds-leader-hrbp-prep.md` 里"前两次投非第一志愿练手"应该前置，不要等到 Q4

---

## 总结

> 这个项目的 ML 和 Agent 内核已经够用了，缺的是把它对外讲述的方式。这一年最关键的不是再加一层调整链或者再训一个模型，而是把现在的这堆东西重新摆放，让人在 60 秒内、5 分钟内、30 分钟内分别能看到不同深度的精彩。

**行动优先级**（建议排序）：
1. 建面向外部的入口（`examples/` + README 重写）
2. Exploration arm（selective labels 解决方案）
3. Agent 系统独立叙事（博客 + 简历重构）
4. Demo 部署 + trace 可视化
5. 提前投递练手面试
