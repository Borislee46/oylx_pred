## 四、海投 vs 精准（核心发现）

| 模式 | 记录数 | Session数 |
|------|--------|-----------|
| 海投 (系统自动匹配所有专业) | 169条 (80%) | 95个 |
| 精准 (手动筛选专业) | 14条 (7%) | 7个 |

- 海投平均覆盖 **527个专业**，最高 1048 个
- **80% 的用户依赖系统自动匹配，几乎没人手动挑专业**
- E5 语义相似度 + TF-IDF 排序质量直接决定 80% 预测的用户体验
- 海投用户中仅 14% 填写了目标学院

## 八、优化建议（A/B 分类修订版）

### 判别框架

用户行为信号分两类，处理方式不同：

| 类型 | 定义 | 处理方式 | 判别标准 |
|------|------|----------|----------|
| **A 类：执行层信号** | 反映用户做事的物理约束（性能、节奏、集中度） | 直接进 backlog 优化 | 优化后系统变好，不会变形 |
| **B 类：意图层信号** | 反映用户在当前 UI 下的理解和妥协 | 回到 vision 层重新设计 | 跟随优化 → 3年后系统会变成什么？ |

---

### A 类信号（直接执行）

| # | 发现 | 为什么是 A 类 | 建议 | 影响面 |
|---|------|--------------|------|--------|
| A1 | 28% 在 30s 内反复提交 | 物理时间约束，跟用户意图无关 | Session 内缓存特征向量，增量计算只重算变更部分 | prediction flow |
| A2 | 69% 记录有迭代调参 | 用户想对比不同参数的结果，这是未满足的认知需求 | 加「对比上次结果」视图，展示参数变化 → 概率变化 | result display |
| A3 | 雅思 89% 集中在 6.0-6.5 | 数据分布事实，不涉及 vision 判断 | 语言 penalty 函数在 6.0-6.5 区间做更细粒度校准 | result_modifier |
| A4 | 双高峰 9am + 3pm | 使用时间分布，纯运维信号 | 高峰前定时预热 st.cache_data；晚间降资源 | main.py |
| A5 | 港三 × TOP3 专业覆盖 77% | 目标集中度，不涉及设计判断 | 为高频组合预计算 E5 + TF-IDF 相似度缓存 | pipeline / precompute |
| A6 | 月度留存极差 (四月仅1人回訪) | 反映使用粘性缺失，跟产品形态有关但不是意图妥协 | 加案例保存/订阅功能，给学生申请进度持续跟踪的理由 | 新功能 |

### B 类信号（回到 vision 层重设计）

| # | 发现 | 错误跟随 | 正确解法 | 影响面 |
|---|------|----------|----------|--------|
| B1 | 80% 海投，7% 精准 | 把产品拍扁成海投，砍精准模式 | 海投是入口模式，精准是决策模式——应做漏斗：海投出 top-20 → 点击进精准模式重新跑 → 最终决策。保留两种模式，让 80% 入口流量自然漏到精准 | pipeline / UI |
| B2 | GRE 97% 为空 | 折叠/移除 GRE 字段 | GRE 是为美国/北美申请路径准备的。当前用户都是港校用户所以不填——但未来扩展美国市场时这就是必要字段。正确解法：**按目标国家自适应展示**（选港校不显示 GRE，选美国才显示） | form_state.py |
| B3 | 86% 不填目标学院 | 放宽跨学院 penalty (×0.3) | 跨学院录取率低是 domain truth（领域硬事实），不因用户填不填而改变。86% 不填说明 **UI 教育失败**，不说明 penalty 不重要。正确解法：保留 penalty，在 UI 做内联教育——"未填学院，当前预测假设所有专业都接受跨学院申请，实际录取率会显著低于此" | result_modifier |
| B4 | 重度用户成熟度 1.0 ≈ 轻度 0.8 | 认定高级功能没价值 | 用得最多的人只是在重复最简单的海投操作路径。说明高级功能（学院筛选、精准选专业）**没被发现**而不是没价值。正确解法：在结果页做内联引导——"试试限定学院，预测更精准""试试精准选专业" | UI 引导 |
| B5 | 四段经历 80%+ 为 0 | 砍掉经历字段 | 经历是否重要是 domain truth 问题，不是频率问题。正确解法：保持字段但降级表单权重——改为二元开关"是否有 XX 经历"，有才展开；默认折叠减轻视觉负担，但不删除 | form_state.py |

### 修订后的优先级

| 优先级 | 编号 | 类型 | 行动 |
|--------|------|------|------|
| P0 | A1 | A | Session 内增量计算（性能瓶颈直接改善用户体验） |
| P0 | B3 | B | 学院 penalty 内联教育（阻止 Goodhart 反馈循环） |
| P1 | B1 | B | 海投→精准漏斗（结构性产品升级而非迁就行为） |
| P1 | A2 | A | 对比上次结果视图（直接满足迭代对比需求） |
| P1 | A5 | A | 港三热门组合预计算缓存 |
| P2 | B2 | B | GRE 按国家自适应展示（为未来扩展留架构空间） |
| P2 | B5 | B | 经历字段改二元开关（减负但不删除） |
| P2 | B4 | B | 高级功能内联引导 |
| P3 | A4 | A | 高峰预热缓存 |
| P3 | A6 | A | 案例保存/订阅 |
