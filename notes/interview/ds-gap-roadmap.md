## 第一层：必补（决定过不过）

### 1. A/B 实验理论基础

**你已有**：灰度、样本圈选、P值、反转 → 感受层

**需要补的术语体系**：

- **Type I Error (α)** / **Type II Error (β)** / **Power (1-β)**
  - 你做的"看 P 是否显著"本质是控制 Type I Error ≤ 5%
  - 但你没提 Power——如果样本量不够，真有效果也检不出来
  - 面试必问："实验不显著怎么办？" → 标准回答："先算 MDE，看当前样本量是否够"

- **MDE（Minimum Detectable Effect / 最小可检测效应）**
  - 一句话：给定样本量，多大差异才能被你检测到
  - 面试中用来回答"为什么不显著"的标准框架

- **Peeking Problem（偷看问题）**
  - 一句话：每天看一次 p 值，等到 p<0.05 那天就停 → 实际 Type I Error 不是 5%，而是 20-30%
  - 你做的灰度测试本质上每天看数据，这就是 peeking
  - 面试常问："实验跑了 3 天 p=0.08，怎么办？" → "不偷看，提前算 MDE 定样本量，到量了再下结论"

- **P-hacking（P值操纵）**
  - 一句话：反复分析同一份数据直到找到 p<0.05 的组合，等于"对着数据开枪，打完画靶心"
  - 你做的灰度测试场景：每天看一次 p 值，第 4 天显著了就兴奋汇报 → 这是最常见的不自觉 p-hacking
  - 还有哪些常见形态：
    - **可选停止**：样本攒到够了才停，但中间看了 5 次 → Type I Error 膨胀
    - **分群挖掘**：全量不显著就拆男女/拆新老用户/拆地域，找到某个分段显著 → 纯粹钓鱼（多重比较变体）
    - **指标切换**：点击率不显著就看转化率，转化率不显著就看留存率 → 同上
    - **异常值取舍**：去掉"那几个极端用户"就显著了 → 如果没预设去噪规则，就是操纵
  - 面试必问："你怎么保证自己没在 p-hacking？"
    - 标准回答："**预注册（pre-registration）**：实验前写好分析计划——主指标是什么、看多久、分不分群、去不去异常值。分析时严格按计划来，偏差记录而不是借口。"
  - 三种防范手段：
    - **固定样本量**：提前算 MDE 定样本量，到量才看结论，中间不偷看
    - **Sequential testing + alpha-spending**：允许中间看，但每次 p 值门槛调高（O'Brien-Fleming / Pocock boundaries）
    - **Bayesian**：放弃 p 值，用后验概率"P(实验优于对照) > 95%"，天然抗 peeking
  - **跟 Peeking Problem 的关系**：Peeking 是无意的（没意识到每天看会膨胀错误率），P-hacking 是有意的（或明知但选择性报告）。前者是统计学无知，后者是学术不端。面试官把这两个捆在一起问。

- **Multiple Testing（多重比较）**
  - 一句话：看了 20 个指标，纯靠运气就会有1个"显著"
  - 解法：Bonferroni correction（最严格）或 FDR（Benjamini-Hochberg，更实用）

- **Stratification（分层采样）**
  - 你圈的"特殊样本"已经在做分层——把同质性的人放在一起分实验组
  - 术语化：按省份/用户等级/历史行为分层，目的是**减小方差**，提高检测力

**推荐资料**：
- Ron Kohavi《Trustworthy Online Controlled Experiments》第 1-6 章
- 网上"AB Testing Interview Questions"合集 + 至少看 10 道真实面经

**面试模拟题**：
> "实验跑了 1 周，核心指标 p=0.04，你觉得可以上线吗？"
> 预期回答：case by case。先确认 (1) 样本量够不够（MDE 算过没？）(2) 有没有偷看（daily peeking 会膨胀 Type I Error）(3) 有没有看多个指标（Multiple Testing）(4) Novelty effect 可能性（新东西前两周天然偏高）。

### 2. 因果推断（AB 不能做的时候）

**你已有**：反转实验 → 这是消除混淆因素的方法

**两个必须掌握的框架**：

#### Diff-in-Diff（双重差分）

核心思想：比较"实验组变化"和"控制组变化"的差值。差值 = 策略的真实效果（减去自然趋势）。

你的场景举例：如果港大 2025 年扩招，怎么判断录取率变化是扩招政策导致的还是学生质量变化导致的？→ 找一所"没扩招但竞争环境类似"的学校当控制组（如新国立），两组的录取率变化差值 = 政策效果。

#### RDD（断点回归）

核心思想：规则从一个阈值断开，阈值两侧的人本质相似，差异来自规则。

你的场景举例：如果 GPA 3.0 以上才能申某学校，GPA 3.01 和 2.99 的学生几乎一样，但一个能申一个不能申。比这两组人的最终去向 → 衡量门槛政策的效果。

**为什么这两个重要**：互联网不总能做 AB（如隐私限制、政策变化、不可撤回的变更），这时因果推断是唯一手段。面试必问。

**面试模拟题**：
> "如果美团想评估'会员涨价 5 元'对用户流失的影响，不能做 AB（影响收入），怎么办？"
> 思路：找到"没涨价但类似的区域/时段"当控制组 → Diff-in-Diff。或者看"涨价前后的流失趋势断点" → ITS（断断时间序列）。

### 3. SQL

**你已有**：日常查数据的 SQL

**互联网要求**：
- 窗口函数：`ROW_NUMBER()`, `RANK()`, `LAG()`, `LEAD()`, `SUM() OVER (PARTITION BY ... ORDER BY ...)`
- CTE（`WITH ... AS`）替代嵌套子查询
- `EXPLAIN` 看懂执行计划 → 知道 `FULL TABLE SCAN` vs `INDEX SCAN` 的区别

**刷题量**：LeetCode SQL hard × 15道，每道自己写完再看答案。

**面试**：通常给现场题（如"找出连续 3 天都活跃的用户"），白板写 SQL，口述逻辑，能讲执行计划加分。

## 第二层：应补（决定评级高低）

### 4. 指标体系设计

**你已有**：DCG 评估搜索质量 → 你已经知道单一指标是不够的

**需要学**：一个结构化框架，面试时遇到"如果给你一个新业务怎么建指标"直接套用。

**推荐框架：OSM（Objective → Signal → Metric）**：
1. **O - 目标**：业务的北极星是什么？（如：用户成功申请到匹配的学校）
2. **S - 信号**：观察什么能衡量目标？（如：用户按推荐列表申请的比例）
3. **M - 指标**：具体的量化定义（如：推荐列表 top-5 中有 ≥1 个被用户采纳为实际申请的 case 比例）

**你还应该知道的指标维度**：
- **North Star**：唯一核心指标（如 DAU / GMV 的下级拆解）
- **Counter Metrics / Guardrail**：保护性指标（你不能为了提高"推荐采纳率"而牺牲"推荐准确率"）
- **Leading vs Lagging**：先行指标（点击率 ← 1天）vs 滞后指标（录取率 ← 3个月）

**面试模拟题**：
> "我们做了一个留学预测系统，怎么定义这套系统的成功？"
> 你的回答框架：O = 帮助顾问提升申请匹配度。S1 = 顾问采纳推荐比例 / S2 = 学生录取成功率 / S3 = Guardrail: 顾问未修改推荐的原因分析。M = 具体量化。

### 5. 概率基础 + Bayesian 直觉

**你已有**：概率调整链（sigmoid、quadratic penalty、flooring）→ 概率分布你已经在用了

**需要补理论**：
- **Beta 分布 + Binomial 共轭** → "实验前认为转化率是 10%，跑了 100 个样本后更新时间..."这就是 Bayesian 的直觉基础
- **Central Limit Theorem 的"What If"** → 如果样本不独立怎么办（session 内行为 auto-correlated）？如果指标是 ratio metric 怎么办？

**面试模拟题**：
> "你的预测系统输出录取概率 68%，怎么向用户解释这个 68% 的含义？"
> 不是"100 个像你的人有 68 个能录"，因为每个人都是独立的 case。更合理的解释："历史上背景类似的申请人中，录取比例为 68%" + 展示概率区间而非精确数字。
