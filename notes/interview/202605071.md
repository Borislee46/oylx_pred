# AI 时代 DS 差异化：从小样本项目到不可替代的叙事

> 2026-05-07

---

## 一、你跟 Vibe Coder 的真正差异（先解 AI 焦虑）

Vibe coding 写出来的代码有几个很容易被面试官识别的特征：

1. **代码能跑，但说不出"为什么不是另一个方案"** — 选 sigmoid 不选 isotonic、选 0.5 不选 0.3、`scale_pos_weight=5` 而不是 SMOTE，AI 默认值用户复述不出来背后理由。

2. **Happy path 完美、Corner case 全漏** — 高分端会怎样、低分端会怎样、跨学部会怎样、新学校 0 个 case 怎么办，这些必须被真实数据洗过才能想到。

3. **没有"跨阶段决策痕迹"** — 6 个月项目里"原本这样写、后来发现 X 问题、改成 Y" 这种连续判断 AI 给不出来。

4. **没有领域硬约束** — `monotonic_constraints` 不会被 AI 主动加上，除非你已经知道"GPA↑ 录取概率必须↑"是这个行业的不可妥协约束。

### 你的项目里恰好这四件事都有真东西：

- **5 层调整链** 不是一次写出来的，是观察到 bad case 后逐层加上去的（GPA 惩罚 → 语言硬门槛 → 跨专业 ×0.5 → 跨学部 ×0.3 → 职业学位降级 → 文本提升）
- **counterfactual + baseline_admit_rate** 是顾问看不懂模型才补的（这就是"你贴着用户做产品"的证据）
- **LLM 三级 JSON 修复**（直接 parse → 轻量正则 → API repair）是被 DeepSeek 真实 bad case 逼出来的，AI 不会主动写
- **`flooring=0.005` 不是 0** — 这一行就是 domain awareness（"教育里没有绝对不可能"）

**结论：** 你的差异不在"代码量"，而在**"提出正确问题 + 被真实数据洗过 + 跨阶段连续判断"**这三件 AI 替代不了的事。

但这些差异面试官点开 GitHub 看不到，这才是你焦虑的真实根源——不是你没做，是你没让人看到。所以解法是：**把决策痕迹"显性化"**。

## 二、小样本不是弱点，是另一种 DS 工种（重新定义你的赛道）

把"小样本 vs 大数据"重新摆位：

| 维度 | 互联网（大数据） | 留学（小样本，你的场景） |
|------|-----------------|------------------------|
| 样本 | 溢出，撒网 AB | 稀缺，每个 case 都珍贵 |
| 决策成本 | 推错一个 item，下一秒补救 | 推错一个学校，申请季报销 + 信心打击 |
| 模型 | 可以大、可以糙，靠数据量兜底 | 必须靠 calibration + monotonic + domain rule 弥补样本量 |
| 评估手段 | 真实 AB 是首选 | AB 不可行 → 必须用 holdback / rolling backtest / counterfactual / OOD 检测 |
| 可解释性 | 可有可无 | 必须可解释，不然顾问不敢用 |

这恰好是"高价值低频决策场景的 ML 教科书"——金融风控、医疗诊断、保险核保、法律 AI、教育推荐、to-B 推荐系统，全是这个工作流。这些团队在大厂里也都在招人，他们要的就是"在小样本 + 高代价场景做 ML"的人。

**所以你的姿态应该是：**

> "我做的不是大盘 ranking，是高代价低频决策场景。这类场景 AB 不可行，必须靠 calibration、monotonic、counterfactual、OOD 三重保险来弥补样本量。我有这套小样本的工作流，搜索 DCG 那段经验则证明我也懂大盘 ranking 的另一套。"

这样讲，"小样本"就从"我没做过大数据"翻译成了"我有大多数候选人没碰过的另一种 DS 能力"。

## 三、扬长避短的叙事模板（直接拿去用）

两段式介绍，2 分钟版：

**第一段 — 字节抖音搜索做泛化项目：**

从垂搜（视频/音乐/用户）扩展到通用搜索，在 Libra 上搭过完整指标树（CTR / 渗透率 / 双持渗透 / LT proxy），用 pairwise + DCG 盲评做 ranking 评估，做过反转实验验证长期效应。这段证明我**懂大数据、懂 AB、懂 ranking 评估体系**。

**第二段 — 独立做的留学录取预测系统：**

典型的"小样本 + 高代价决策"场景，AB 不可行，必须靠别的手段保证可靠性。做了三件事：

- **模型层：** XGBoost + monotonic constraints（GPA↑ 录取↑ 是行业硬约束）+ sigmoid calibration
- **后处理层：** 5 层概率调整链（GPA / 语言 / 跨专业 / 跨学部 / 文本提升），每一层对应一个被真实 bad case 教训过的领域规则
- **验证层：** counterfactual 反事实分析、OOD 三级分级、rolling backtest 模拟时间漂移

两段合起来：一个证明我懂大盘 scale，一个证明我能在数据稀缺场景做 0-1 的独立闭环——而且我有真实数据上跑过的统计模拟（peeking / power / multiple testing），所以即使没有 AB 平台，我对实验思维的训练是有数字做证的。

### 关键技巧：

1. **先讲大数据那段** — 立刻打消"你没做过互联网 scale"的疑虑
2. **再讲小样本这段** — 把它包装成"互联网 DS 不擅长的另一类问题"
3. **每段都用术语** — pairwise / 反转 / DCG / monotonic / calibration / counterfactual / OOD —— 让面试官知道你不只是在做事，是在用学术词汇思考

## 四、显性化"决策痕迹"的具体动作

回到你最焦虑的点："Vibe coder 也能做出来这个项目"——解法是让你的判断过程可见。三件事，每件都不大，但每件都让 vibe coder 复刻不出来：

### 动作 1：在仓库根新建 `DECISIONS.md`（最重要）

不是 README，是决策日志。每条 50-150 字，格式：

```markdown
## DEC-001: 为什么用 sigmoid 而不是 isotonic 校准

日期: 2025-XX
背景: 训练集 ~12000，holdout ~2400
观察: isotonic 在 holdout Brier 略好（0.182 vs 0.185），但 reliability
      diagram 显示在低概率段（<0.2）出现非单调阶梯——业务上不可接受。
决策: 选 sigmoid，牺牲 0.003 Brier 换概率单调性 + 平滑性。
后果: 顾问反馈"概率排序更直观了"，未再投诉概率反转。
```

这种文档面试官点开 = 直接看到你的判断深度。Vibe coder 写不出来，因为他没有这些"曾经"。

写 8-12 条覆盖项目最关键的决策 — 5 层调整链每一层、calibration、threshold、SMOTE 与否、monotonic 范围、Streamlit 选型、LLM Agent JSON 修复策略。2-3 个小时的活，但价值远超你想象。

### 动作 2：在每个核心模块写"WHY 注释"

Vibe coder 不会写 WHY，只会写 WHAT。对比：

```python
# WHAT: 不写
LANG_CRITICAL_THRESHOLD = 5.5

# WHY: 写
# 5.5 来自 2024 年港校研招 FAQ 公开门槛——低于此基本无视申请。
# 不是从数据学出来的（样本里 <5.5 的 case 太少无法统计），
# 是 domain rule 直接硬编码。如果未来雅思官方调整或港校放宽，
# 此处必须同步更新（已在 admin/whitelist 加了管理员可配项）。
LANG_CRITICAL_THRESHOLD = 5.5
```

这种注释告诉面试官你做过功课、你考虑过未来变更、你不是把 magic number 复制粘贴过来。

### 动作 3：把"被 bad case 教训过"的故事写到 README

在仓库根 README（英文版）加一个 section：**Lessons Learned**

- **LLM JSON output:** DeepSeek 在 1.2% 的请求会输出尾部多余逗号 → 添加了 lightweight regex 修复（<1ms），修复失败再走 API repair。
- **Cross-faculty cases:** 3% 的学生跨学部申请，初版直接走主流程会预测出"理学院申文学院 65%"的荒谬结果 → 加了 ×0.3 惩罚 + 二次确认弹窗。
- **High-GPA OOD:** GPA > 3.95 的极少数学生（清北本+保研竞争者），原始 XGBoost 预测会拉到 90%+，超过训练数据见过的最高点 → 改用"高分端透出 + 低分端 flooring"的非对称 OOD 策略。

每条都是真实的、AI 生成不出来的、被业务洗过的案例。三五条这种"踩过的坑"远胜十条 feature 列表。

## 五、一句话总结

> AI 时代 DS 的护城河，不在"我能写多复杂的代码"，而在"我能提出多对的问题 + 我有多少真实数据洗过的判断 + 我能讲清楚为什么不是另一个方案"。

你的项目这三样都有，但都藏在代码里没浮出来。

下一步不是再写新功能，而是花一个周末把上面三个"显性化"动作做完 — `DECISIONS.md` + WHY 注释扩展 + Lessons Learned section。

做完之后，你的简历点开看到的不再是"一个能跑的系统"，而是"一个有判断过程留痕的工程师"。这就是 vibe coder 永远拿不出来的东西。
