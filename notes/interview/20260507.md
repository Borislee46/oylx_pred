# 项目体检诊断 & 30 天"惊艳化"路线

---

## 整体判断

你这个项目作为"国内 DS / 策略 DS 求职作品"，**地基已经超过 80% 候选人**——XGBoost + sigmoid calibration、monotonic constraints、5 层调整链、counterfactual 反事实、trace 可视化、LLM Agent（含流式 + JSON 三级修复）、Algorithm Lab、HR/CS 多模块——这些都是真东西。

但要做到"惊艳"，问题不在功能广度，而在**三个面试官最容易扣分的点**：

1. **没有"研究型证据"** — `notes/interview/project-validation-plan.md` 已经把 V1-V4 / S1-S6 都设计好了，但代码里一个图表都没产出。面试官点开你的 GitHub，看不到 reliability diagram、ablation 矩阵、bootstrap 特征排名，只能看到一个能跑的系统。系统再好都是"工程作品"，不是"DS 作品"。

2. **没有对外可触达的窗口** — 系统是 Streamlit 单机内部用的，README 是中文，没有 demo 链接，没有博客。面试前面试官能看到的只有简历上一行字。

3. **缺"AI 时代的差异化叙事"** — 你已经有 6 个 LLM Agent，但没有 Agent eval、没有 prompt 版本管理、没有 LLM 失败模式分析。在 2026 年，这是真正能拉开差距的地方，你笔记里都没强调它。

## 按"性价比"排序的补全清单

### 优先级 P0（必须补，不补就只是个工程项目）

#### 1. 把 V1-V4 实验跑出来，结果做成 `reports/` 子目录

`project-validation-plan.md` 里写得非常完整，但都是文字，没有产物。建议在仓库根新建：

```
reports/
├── v1_calibration/
│   ├── reliability_diagram.png        # 校准前 vs 后 两条曲线
│   ├── brier_decomposition.json       # Calibration / Refinement / Uncertainty 三项
│   ├── ece_per_bin.csv                # 10 个 bin 的 ECE
│   └── notebook.ipynb                 # 可复现
├── v2_ablation/
│   ├── kendall_tau_matrix.png         # 5 层 × 200 case 的影响矩阵
│   └── extreme_cases.json             # 每层影响最大的 3 个 case trace
├── v3_threshold_sensitivity/
│   └── cost_threshold_curve.png       # cost ratio 0.2~5.0
└── v4_feature_bootstrap/
    └── feature_rank_box.png           # 1000 轮 bootstrap
```

**为什么这个最重要：** 你简历上已经写了"sigmoid calibration"，但面试官追问"Brier 降了多少"时你只有 0.185 这个原始数字——你笔记里自己都发现了"predicted 54.9% vs actual 33.7% 高估 21%"，**这是个金矿**，做成图就是面试爆点。

#### 2. 新建 `experiment-simulations/` 独立模块

这是笔记里 Albert 给你的最核心建议（"S2-S6 单独成 repo，本身就是 DS 实验思维 portfolio"），但你项目里完全没有这个目录。

```
experiment-simulations/
├── README.md                          # 英文，讲"没有 AB 平台怎么做实验思维训练"
├── peeking/
│   └── peeking_problem_demo.py        # 复现 Type I Error 5% → 25% → 45%
├── multiple_testing/
│   └── bonferroni_vs_bh.py
├── power/
│   └── mde_curve.py                   # 用项目真实 baseline 34% 算
├── stratification/
│   └── stratified_vs_random.py
├── ood/
│   └── ood_three_tier.py              # 用 cases.feather 算每特征分位数

    └── time_window_drift.py
```

**为什么差异化：** 90% 的国内 DS 候选人会背 Kohavi 的定义，但没人在自己项目数据上跑过模拟。这一个目录就是你跟其他人的护城河，比再加 3 个特征工程有用 10 倍。

#### 3. 写一份 `MODEL_CARD.md`（Google 标准格式）

放在 `src/machine_learning_models/MODEL_CARD.md`，结构对标 Google Model Cards：

| 章节 | 内容 |
|------|------|
| Model Details | XGBoost + Calibration 版本号、训练日期、特征维度 |
| Intended Use | 顾问辅助、不可作为唯一决策依据 |
| Out-of-Scope Use | 不能直接给学生看 raw 概率 |
| Training Data | 样本量、时间范围、地理覆盖、已知偏差 |
| Evaluation | Brier / AUC / ECE / 分组 fairness |
| Ethical Considerations | selective labels、self-fulfilling prophecy |
| Known Limitations | 新学校冷启动、政策变化滞后 |

**为什么是 P0：** 你笔记里反复提到 selective labels、self-fulfilling prophecy 这些词，但项目里没有对应的"诚实声明"。Model Card 是 senior DS 的标志，有它就跟一般候选人拉开了一个层级。

#### 5. LLM Agent 评估框架（你这个项目的"AI 时代"卖点）

你有 LeadInAgent / ExplainAgent / BoundaryCaseAgent / TextPreprocessingAgent / BackgroundFacultyAgent 5 个 Agent，但项目里没看到对应的 eval。建议加：

```
src/agent/eval/
├── eval_dataset.jsonl               # 50-100 个标注好的 input → expected output
├── lead_in_metrics.py               # 字段抽取 F1 (university/major/gpa/...)
├── explain_metrics.py               # 长度合规 / 关键词覆盖 / JSON 解析成功率
└── regression_test.py               # CI 跑：新 prompt 不能比旧版本掉点
```

面试 2026 年聊"你怎么验证 LLM 不胡说八道"时，这个就是你的答案。

---

#### 6. Drift / Monitor 离线脚本

不需要真的上线监控系统，就一个能在 cron 里跑的脚本：

```
scripts/monitor/
├── psi_check.py                     # 训练分布 vs 最近 30 天数据，PSI > 0.2 报警
├── calibration_drift.py             # 用最新 holdout 重算 Brier，对比基线
└── feature_distribution_report.py   # 输出 markdown 报告
```

这是你笔记里 Q7 "Concept drift detection" 的实证答案。
