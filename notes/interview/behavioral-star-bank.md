## 面试话术要点

**说失败时**：
- ❌ "项目失败了因为别人不配合" → 甩锅
- ✅ "我当时的选择是 X，后来发现应该做 Y。之后我建立了 Z 机制防止再犯" → 自察+成长

**说冲突时**：
- ❌ "PM 不懂技术，非要我做..." → 攻击性强
- ✅ "PM 关心用户体验，我关心模型准确率，我们其实目标一致但优先级不同。最后我..." → 尊重对方立场

**说取舍时**：
- ❌ "我选 A 因为 A 更好" → 没思考深度
- ✅ "A 和 B 的 tradeoff 是 X vs Y。在当前阶段，我优先 X 因为..." → 有决策框架

## 填写策略

1. 先写出每个故事的事实版本（不用 STAR，就是发生了什么）
2. 再从事实里提取 S/T/A/R/Learn
3. 录一遍自己讲 → 回听 → 改掉啰嗦/甩锅/抱怨的语气
4. 每个故事控制在 2 分钟内

**你的素材池**（不需要全用，挑真正发生过的）：

| 场景 | 可能的素材 |
|------|-----------|
| 失败 | 模型某个版本上线后效果不好？某个特征工程方向走错了？概率调整系数拍脑袋后来发现不对？ |
| 冲突 | 和顾问在某个预测结果上有分歧？和老板在公司数据文化推动上有分歧？ |
| 取舍 | 概率调整链里为什么选 0.5 不选 0.3？为什么选 Streamlit 不选 FastAPI？为什么不做深度学习？ |
| 反对上级 | 有没有老板让你做某件事你觉得不对的？有没有被要求美化数据的时刻？（Q12 的变形） |
| 承压 | 同时被多个需求催？系统出 bug 被顾问投诉？DDL 前模型还没调好？ |
| 复盘 | 做完一个季度后回头看，最大的意外是什么？ |

## 完成后对照 `ds-leader-hrbp-prep.md` 自查

把写完的 4 个故事对照 HRBP 踩坑清单逐条检查：

- [ ] 没有任何一句抱怨前司/前老板
- [ ] 每个失败/冲突故事都以"我学到了"收尾
- [ ] 没有包装成"我太努力了"这种虚伪答案
- [ ] 展现的是务实、开放、追求极致（字节价值观）
- [ ] 说完后面试官不会怀疑你的稳定性和团队兼容性
