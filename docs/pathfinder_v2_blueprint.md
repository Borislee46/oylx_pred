**核心原则**：新数据只影响"怎么展示"，不影响"怎么预测"。XGBoost 训练数据保持纯净。

三层递进：
1. **预测层**（已有）：XGBoost → 你的概率
2. **对比层**（反推卡片）：学校画像 → 你要成为谁
3. **行动层**（What-If）：反事实模拟 → 你该做什么

## 二、外部数据：现状与设计决策

### 2.1 两组数据

| | Compass（指南者） | ApplySquare |
|---|---|---|
| 性质 | 竞品案例库 | 全球留学论坛开源数据 |
| 清洗后规模 | 17,194 行 × 21 列 | 1,624 行 × 20 列 |
| 录取/拒绝 | 100% 录取 (survivorship bias) | 85% 录取 / 15% 拒绝 |
| 核心优势 | 经历描述丰富、学校名完整 | 有拒绝案例、GRE/GMAT |
| 核心劣势 | 无拒绝案例 | 本科学校56%缺失、学校名是tier标签 |
| 文件 | `data/external/compass.feather` | `data/external/applysquare.feather` |

**互补关系**：Compass 回答"典型录取者长什么样"，ApplySquare 回答"录取vs拒绝差在哪里"。

### 2.2 为什么不混入 XGBoost 训练

三组数据的分布本质不同，不是数据量问题，是分布问题：

- **XDF**：付费找XDF做申请的中国学生，特定分布
- **ApplySquare**：全球自发报offer，self-selection bias（高段位更愿晒，失败不愿晒）
- **Compass**：竞品案例库，严重 survivorship bias（全是录取）

混入训练 → 模型可能学到数据源 artifact（"来自Compass的=admitted=1"），而非真实录取规律。

**架构选择：Multi-Source Evidence，不是 Multi-Source Training。**

| 维度 | 混入训练 | 独立证据层 |
|------|---------|-----------|
| 预测纯度 | 受污染 | 不受影响 |
| 可迭代性 | 重训才能更新 | 热更新，独立部署 |
| 可解释性 | 模糊 | 清晰（"XDF说你X%，外界参考Y"） |
| 回滚风险 | 重训 | 关模块 |

### 2.3 数据质量（Phase 0 已完成）

清洗脚本：`scripts/clean_external_data.py`
专业名映射：`config/major_name_mapping.json`（576 auto-mapped, 57 new）

| 质量指标 | Compass | ApplySquare |
|---------|---------|-------------|
| GPA 有效 (0-4.0/5.0) | 98.5% | 83.4% |
| IELTS 有效 | 80.2% | 50.6% |
| TOEFL 有效 | 6.8% | 29.2% |
| 专业名匹配XDF | **97%** | **89%** |
| Count字段合理范围 | ✓ | ✓ (已cap@10) |

**已知残余问题**：
- Compass 210行 GPA 4.0-5.0，可能为5.0分制未归一化（不影响P50计算，量小）
- ApplySquare `background_university` 56%为tier标签（`[双非]`、`[211]`），非真实校名
- ApplySquare 行级重复（576唯一学生→1624行，一人申多校），分析时需注意

**使用约束**：
- 样本量<20的学校+专业组合 → 标注"数据不足"，不展示画像
- 展示层每个统计数字标注数据来源（XDF/Compass/ApplySquare）
- 指南者survivorship bias需在UI注明"基于N份录取案例"
- 外部数据不参与 `admission_cache`

## 三、证据层：五大分析

按实现难度和产品价值排序：

### 3.1 学校画像（🥇 最先做）

**"学校喜欢什么样的学生"**

三层结构：

```
┌─────────────────────────────────────────────┐
│ 🎯 冲刺校画像  │  港大 BA                     │
├─────────────────────────────────────────────┤
│ 典型录取者（Compass P50, N=XXX）              │
│  GPA 3.65   语言 7.0   科研 2段   实习 1段   │
├─────────────────────────────────────────────┤
│ 该校最看重的维度（ApplySquare Cohen's d）     │
│  科研经历 ████████ d=0.8 (大效应)            │
│  语言成绩 ██████   d=0.6 (中效应)            │
│  GPA      ████    d=0.4 (小效应)            │
│                                             │
│ → 想去港大BA，科研比GPA重要                   │
├─────────────────────────────────────────────┤
│ ⚡ 你的差距                                   │
│  科研少1段 (录取者中位2段 vs 你1段)            │
│  语言达标 (录取者中位7.0 vs 你7.0)            │
│  GPA差0.2 (录取者中位3.5 vs 你3.3)           │
└─────────────────────────────────────────────┘
```

- **P50画像**：per-school per-feature 中位数，Compass 主力 (17K data)
- **差异分析**：录取组 vs 拒绝组 Cohen's d，取 top-3，ApplySquare 主力 (237 reject)
- **ROI建议**：哪个维度差距最大+效应量最高 → 建议优先补

### 3.2 反事实模拟 / What-If Engine（🥇）

**用户不要判决，要"我该干什么"。**

逐个维度模拟提升收益：

```
当前 → GPA 3.2→3.4  → 概率 15%→30% (+15%)
      → 雅思 6.5→7.0 → 概率 30%→38% (+8%)
      → 科研 1段→2段  → 概率 38%→52% (+14%)

ROI最高：科研 (+14%)，其次 GPA (+15%)，语言最低 (+8%)
建议优先补科研经历
```

实现方式：复用 XGBoost 模型，逐列调整输入后重新推理。每次单变量变化，保持其他维度不变，计算边际效应。

产品价值：直接回答"我该报什么班"——顾问最好的转化工具。
DS叙事价值："我们的模拟基于 XGBoost + 外部数据 counterfactual evaluation"。

### 3.3 阈值发现（🥈）

**虽然没有正式录取线，但数据里有 "observed minimum"。**

统计 ApplySquare reject 案例：
- 港大 BA：录取者 GPA 最低 3.1，低于3.1的申请者全部被拒
- 港城 Marketing：录取者 GPA 最低 2.7

产品上："你的 GPA 3.0，低于该专业历史录取最低 3.1，建议补科研弥补"。给顾问一个说话的锚点。注意标注"基于N个案例，非官方录取线"。

### 3.4 XDF 优势反证 / 对抗验证（🥉，叙事重头）

**不是"我觉得 XDF 好"，是用数据证明 XDF 好在哪。**

方法一（简单）：对比分析
- XDF vs ApplySquare 在相同 GPA/语言/本科 tier 下的录取率差异
- XDF vs Compass 在科研/实习经历段数上的差异

方法二（进阶）：训练一个分类器区分"这条数据来自 XDF / ApplySquare / Compass"。如果容易区分，输出特征重要性 → 精确量化"XDF 学生到底特殊在哪"。

可能的发现：
- "XDF 学生科研经历显著更多" → XDF 帮学生补科研
- "XDF 学生选校更聚焦（跨专业比例更低）" → 预测系统+顾问有效
- "XDF 学生低GPA录取率更高" → XDF 文书/包装有加成

每一条结论都可复现，面试时能讲的可检索证据。

### 3.5 跨国套利分析（远期）

**相同背景，不同国家的录取率差异。**

"跟你背景相似的人，60%去了香港，其实你也该看看新加坡的XX学校，录取率高15%。"

产品上变成一个推荐卡片，DS叙事上 = "留学市场的 inefficiency 发现"。

### 3.6 选校组合优化（远期）

给定学生背景，最优选校组合 = 投资组合优化问题：
- 不确定性 = 录取概率
- 约束 = 申 N 所
- 目标 = 最大化预期收益（进最好的学校）+ 控制风险（至少中一所）

"用马科维茨模型做留学选校"——独立成文的好话题。

## 四、产品洞察：从判决到行动

> 核心洞察来自 2026-05-12 讨论。

**用户不要既定事实的判决，要动态可变化的过程。**

| 现状 | 改进方向 |
|------|---------|
| "你录取概率15%" → 用户感觉没救了 | "你GPA提0.2就变30%" → 有希望 |
| 展示统计事实 | 展示行动指南 |
| 学校卡片的概率条 | 概率条 + 提升模拟 |
| 技术正确 | 技术正确 + 营销可用 |
| 忽略时间维度 | 大二有空间 vs 大四已定型 |

**反推卡片的正确设计**：不只是"你差在哪"，更是"你能怎么追"。

- 每个 gap 附带"如果补齐，概率预估提升 X%"
- 标注"ROI 最高"的维度
- 加入年级维度：大二 → 全可补，大四 → 重在选校策略
- 概率调整链的每一步（GPA惩罚、语言惩罚、跨专业惩罚）都可反转为"消除惩罚 → 回升X%"

## 七、注意事项

- **XGB 训练数据不变**：外部数据绝不出现在训练集中
- **样本量门槛**：n<20 → 标注"数据不足"
- **数据源标签**：展示层每个统计标注来源
- **survivorship bias**：Compass 注明"基于N份录取案例"
- **非录取线声明**：阈值发现结果标注"非官方录取线，基于N个案例"
- **外部数据缓存独立**：不参与 `admission_cache`
- **ApplySquare 本科弱**：涉及本科学校的功能标注完整度
