# 外部数据集成方案：ApplySquare + 指南者

> 2026-05-11 讨论记录。状态：数据抓取完成，待清洗。
>
> 长期定位：从"XDF内部预测工具"走向"泛化留学选校系统"的核心数据基座。

## 1. 背景与目标

XDF 内部训练数据（`cases_min.feather`）稳定支撑 XGBoost 模型，不打算动。新引入两组外部数据：

| 数据源 | 类型 | 有失败案例 | 有学生key | 信息丰富度 | 用途定位 |
|--------|------|-----------|-----------|-----------|---------|
| **ApplySquare** | 全球留学论坛随机捞取 | 有（录取+拒绝） | 有 | 中等 | 录取vs拒绝差异分析、外部分布校准 |
| **指南者** | 竞品（行业同行） | 无（仅录取） | 无 | 高（比XDF更全） | 典型录取者画像、反推卡片主力 |

**核心原则**：新数据只影响"怎么展示"，不影响"怎么预测"。XGBoost 训练数据保持纯净。

## 2. 设计决策：为什么不能混入训练

### 2.1 三组数据的分布本质

```
XDF 内部数据        →  有边界的人群：付费找XDF做留学申请的中国学生，
                       主力目标港新。GPA段位、本科tier、申请激进程度
                       构成一个特定分布。

ApplySquare         →  全球论坛自发报offer/rejection的人群。
                       存在 self-selection bias：高段位更愿意晒，
                       失败更不愿意晒。分布 ≠ 一般申请者。

指南者              →  竞品案例库，只有录取没有拒绝。
                       严重的 survivorship bias——
                       任何从"全是成功案例"学到的规律，
                       都混淆了"学校偏好"和"申请者自筛选"。
```

**不是数据量的问题，是分布的问题。** 把三种不同分布、不同bias的数据拼在一起训练，模型学到的不一定是"录取规律"，而可能是数据来源的artifact——比如"来自指南者的=admitted=1"这种假关联。

### 2.2 特征维度不对称

XDF有结构化的 `faculty`、`background_major_original`，外部数据没有。硬补零或中位数会让这些feature产生"缺失=来自外部数据源=label分布不同"的虚假信号。XGBoost的树分裂天然会利用这种信号，即使它不代表真实的录取规律。

### 2.3 架构选择：Multi-Source Evidence，不是 Multi-Source Training

```
┌─────────────────────────────────────────────────────────────┐
│                    系统边界                                  │
│                                                             │
│  XDF数据 (in-distribution)                                  │
│    │                                                        │
│    ├──→ XGBoost 预测模型                                    │
│    │      └──→ 概率调整链 (规则)                            │
│    │             └──→ 【最终概率】                           │
│    │                                                        │
│  ─ ─ ─ ─ ─ ─ ─ ─ 证据分层边界 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─        │
│                                                             │
│  外部数据 (out-of-distribution)                              │
│    │                                                        │
│    ├──→ 画像模块 (P50, gap)     ─→ 【反推卡片】              │
│    ├──→ 差异分析 (Cohen's d)    ─→ 【学校偏好】              │
│    ├──→ 相似检索 (k-NN)         ─→ 【竞争画像】              │
│    └──→ 校准检验 (reliability)  ─→ 【模型监控】              │
│                                                             │
│  两套证据体系独立运行，交汇于展示层                           │
└─────────────────────────────────────────────────────────────┘
```

**这不是"模型泛化"，这是"系统泛化"。**

| 维度 | 混入训练 | 独立证据层 |
|------|---------|-----------|
| 预测纯度 | 受污染，artifact risk | 不受影响 |
| 业务专家信任 | 可能动摇 | 维持 |
| 可迭代性 | 重训才能更新 | 热更新，独立部署 |
| 可解释性 | 模糊("更多数据") | 清晰("XDF说你X%，外界参考Y") |
| 回滚风险 | 需要重训回滚 | 关掉模块即可 |
| DS叙事 | "我合并了更多数据" | "我设计了多源证据架构" |

### 2.4 需要持续警惕的问题

1. **分布偏移监控**：外部数据只做展示层，但展示的信息（P50、差异维度）会随时间变化。需要定期刷新外部数据，但不需要重训模型。
2. **样本量门槛**：某学校某专业在外部数据中案例太少（<20），则该专业的画像/差异分析不应展示——标注"数据不足"。用户看到的不是"0条数据"，而是诚实的缺失。
3. **数据源标签透传**：展示层每个统计数字需标注数据来源（XDF/指南者/ApplySquare），用户有权知道"这个画像基于谁的案例"。这也是合规上的自我保护——用的是公开信息+竞品数据，来源透明。
4. **不与XDF概率混为一谈**：UI上反推卡片和概率卡片要有视觉区分，防止用户误以为"外部画像 = XDF预测"。
5. **指南者survivorship bias的展示处理**：典型画像基于全录取案例，需要在卡片上注明"基于N份录取案例的中位数"，让用户意识到这是"成功者的样子"而非"申请者的样子"。

## 4. 分层架构

```
Layer 1: XGBoost (FROZEN)
  └── 训练数据：仅 XDF cases_min.feather
  └── 输出：base probability

Layer 2: 概率调整链 (不动)
  └── GPA/语言偏差惩罚 → 跨专业×0.5 → 跨学院×0.3 → TF-IDF提升
  └── 输出：final probability

Layer 3: Stats & 展示层 ← 【新数据在这里发挥作用】
  ├── SchoolFeatureStats 百分位    → 三组数据合并计算
  ├── 反推卡片"典型录取者画像"    → 指南者主力
  ├── 反推卡片"学校看重什么"       → ApplySquare（录取vs拒绝差异）
  └── 模型校准参考                 → ApplySquare做外部检验
```

### 5.3 count 字段的最难环节：经历拆分+分类

指南者的 `主要经历` 字段（eg）：
> "首创证券实习生；某供应链管理有限公司仓储与物流管理实习生；中国某设备招标中心项目管理实习生；基于某银行对于农村金融发展的探索；上证某欧式期权研究；"

5段经历，需自动分类：
- 前3段含"实习"关键词 → `internship`
- 后2段看似研究/项目 → `research`
- 无明确paper关键词 → 不计入 `paper`
- 无明确获奖关键词 → 不计入 `award`

**建议方案**：关键词规则 + 少量手工标注做 ground truth 校验。不要上复杂模型——这个分类任务规则覆盖率高。

## 6. 学校 & 专业名称对齐

**这是最大的工程难点**。三组数据来源不同，学校/专业名称必然不统一。

### 6.1 对齐策略

```
优先级1：精确匹配 XDF 内部的 target_university / target_major 取值集合
优先级2：rapidfuzz 模糊匹配（阈值 >= 85%），人工抽查 top 100
优先级3：手动映射表（config/school_name_mapping.json）
优先级4：无法对齐的 → 标记为 external_only，不参与 XDF percentile 计算
```

### 6.2 专业名称对齐额外挑战

- 同一专业不同叫法："Business Analytics" vs "Business Analysis" vs "BA"
- 中英文混杂：指南者可能用中文专业名
- 粒度不一致："Data Science" vs "Data Science (Machine Learning track)"

建议：专业对齐先用 `rapidfuzz.token_sort_ratio`（对词序不敏感），再用 `rapidfuzz.partial_ratio` 处理长短文本匹配。

### 6.3 映射表文件

```
config/school_name_mapping.json    # 外部学校名 → XDF 内部名
config/major_name_mapping.json     # 外部专业名 → XDF 内部名
```

首次生成用 rapidfuzz + 人工审核 top-N 高频项，后续维护手工添加。

## 8. 反推卡片（Reverse Inference Card）

### 8.1 概念

现有学校卡片是 **"你→学校"**：你的条件 → 录取概率 + 历史百分位。

反推卡片翻转视角为 **"学校→学生"**：
- 选一个**概率最低 + 专业最相似**的冲刺校（避免跨专业误伤）
- 展示这个学校**喜欢什么样的学生**——典型录取者画像
- 展示**你和典型画像的差距**

### 8.2 选校逻辑

在用户选校列表中，加权取最冲刺+最相似的：

```
score = prob_rank × 0.6 + (1 - major_similarity) × 0.4
```

- `prob_rank`：概率在全选校列表中的分位（越低越冲刺）
- `major_similarity`：与用户首选专业的 rapidfuzz 相似度
- 取 score 最低的学校作为反推卡片对象

### 8.3 卡片内容结构

```
┌──────────────────────────────────┐
│ 🎯 冲刺校画像  │  港大 BA        │  ← 特殊标签区分
├──────────────────────────────────┤
│ 典型录取者画像（中位数）          │
│  GPA 3.65   语言 7.0   科研 2段  │  ← 指南者数据算P50
│  ████████   ██████    ████      │  ← 用usc-stat类似的小格子
├──────────────────────────────────┤
│ 该专业最看重的维度                │  ← ApplySquare录取vs拒绝差异
│ • 科研经历（录取者平均多1.5段）  │     效应量Cohen's d top-3
│ • 语言成绩（7.0+占比80%）        │
├──────────────────────────────────┤
│ ⚡ 你的差距                       │
│ GPA差0.2 | 语言达标 | 科研少1段  │  ← 快速gap scan
└──────────────────────────────────┘
```

### 8.4 数据来源对应

| 卡片区域 | 数据来源 | 计算方法 |
|---------|---------|---------|
| 典型录取者画像 | 指南者为主，XDF补充 | per-school per-feature P50 |
| 学校看重维度 | ApplySquare（有拒绝案例） | 录取组vs拒绝组 Cohen's d，取top-3 |
| 你的差距 | 用户输入 vs P50画像 | 简单差值 + 方向判断 |

### 8.5 样式方案

- 沿用 `.usc-card` 外层容器，保持与其他卡片视觉一致
- 2列 grid 中等宽混排，变6张卡片刚好3行 (2+2+2)
- 内部布局不同：不用概率条，用画像格子 + 差异列表
- 可选：轻微色调区分（如淡紫色边框）暗示"这是不同视角的卡片"

  4. 你的差距：快速gap scan

### Phase 3: 泛化面功能矩阵（~2个月，核心差异竞争力）

> 以下功能全部基于外部数据，不碰XGB，但显著提升产品的"泛化感"和专业度。

#### 3a. 跨数据源校准分析（~2周）
- [ ] XDF模型在 ApplySquare 案例上的校准曲线（reliability diagram）
- [ ] 按国家/地区的偏差分析：XDF模型在香港数据上训练，英国/美国预测是否系统性偏乐观？
- [ ] 生成 `calibration_report`：如有系统性偏差，记录方向和量级（不自动调整，人工判断）

#### 3b. 学校录取偏好剖析（~2周）
- [ ] 利用 ApplySquare `总结标签`：统计某学校REJECT案例的标签分布
  - eg. 港大BA的REJECT案例中"中等语言成绩"占比高 → 该校BA看重语言
- [ ] 利用 ApplySquare GRE/GMAT：某学校某专业的标化成绩重要性评分
- [ ] 产出 `school_preference_profile`：每个学校+专业的录取偏好卡片数据

#### 3c. 竞争画像对比（~2周）
- [ ] 相同背景学校+专业组合下，ApplySquare全球案例 vs XDF香港案例的录取率对比
- [ ] "你的竞争对手画像"：同一目标学校+专业的申请者群体特征分布（什么背景的人在跟你竞争）
- [ ] 展示时用：`你的GPA在该校申请池中排X%，你的科研经历排Y%`
  - 注意：这里的"申请池"来自外部数据（指南者+ApplySquare），不是XDF内部

#### 3d. 外部案例相似检索（~2周）
- [ ] 基于学生特征向量（GPA+语言+经历段数+学校tier），从外部数据中检索 top-K 最相似案例
- [ ] 展示相似案例的录取结果分布："跟你最像的20个外部案例中，60%录取、40%拒绝"
- [ ] 点击可展开查看具体相似案例（脱敏后：本科学校tier、GPA、语言、经历概要）
- [ ] 作为反推卡片的补充证据链

### Phase 4: 可选远期

- [ ] 外部数据驱动的辅助校准模型（轻量logistic regression，仅当XGB置信度低时介入）
- [ ] 专业相似度矩阵的定期更新（用外部新专业名扩充）
- [ ] ApplySquare按年份的趋势分析（录取标准是否逐年变化）

## 10. 注意事项

- **XGB 训练数据不变**：外部数据绝不出现在 `cases_min.feather` 中，只读不写
- **名称对齐是最大工程**：抓数据容易，洗数据——特别是学校/专业名对齐——是真实的工作量。指南者是中文名，ApplySquare是英文名，XDF是中英混杂
- **指南者无拒绝案例**：不影响反推卡片使用（画像只需要录取者），但影响 Phase 3 部分功能的覆盖范围
- **外部数据不参与 admission_cache**：缓存 key 基于 XDF 内部数据指纹，外部数据更新不应使预测结果变化
- **ApplySquare 本科缺失 53%**：`background_university` 字段外部数据天生弱，涉及本科学校的功能需要标注数据完整度

## 11. 泛化面愿景：从预测工具到决策系统

```
              ┌─────────────────────────────────────────────┐
              │              Pathfinder 选校系统              │
              │                                             │
 用户输入 ──→ │  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
  GPA/语言/  │  │ XGBoost  │  │ 概率调整 │  │ 展示层   │  │
  经历/目标  │  │ (XDF)    │  │ (规则)   │  │          │  │
              │  │ FROZEN   │  │ FROZEN   │  │ 🟢 现有  │  │
              │  └──────────┘  └──────────┘  │  学校卡片 │  │
              │                              │  百分位   │  │
              │  外部数据层（新）               │          │  │
              │  ┌──────────────────────┐    │ 🟡 反推卡片│  │
              │  │ 指南者 28K            │    │  录取画像  │  │
              │  │ ApplySquare 7K        │    │  偏好维度  │  │
              │  │                      │    │          │  │
              │  │ → per-school P50画像  │    │ 🟠 泛化面 │  │
              │  │ → 录取vs拒绝差异       │    │  外部校准  │  │
              │  │ → 竞争池分析           │    │  竞争画像  │  │
              │  │ → 相似案例检索          │    │  相似案例  │  │
              │  └──────────────────────┘    │          │  │
              └─────────────────────────────────────────────┘
```

**DS叙事线**：这不是一个"套XGBoost的Streamlit表单"。这是一个从单一数据源预测出发，逐步引入多源外部数据、统计检验、效应量分析、相似性检索的**完整决策系统**。泛化面不是改模型架构，而是在模型之上构建数据驱动的多维度信息层——让用户看到的不是"你有多大可能进"，而是"你要面对什么样的竞争池，高概率录取的人长什么样，你和他们的gap在哪"。

三层递进：
1. **预测层**（已有）：XGBoost → 你的概率
2. **对比层**（反推卡片）：典型画像 → 你要成为谁
3. **泛化层**（Phase 3）：竞争池 → 你的对手是谁，相似的人走到了哪里
