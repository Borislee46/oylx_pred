> 原则：面试官问你一个数字你能答出"怎么算的"，问你一个动词你能答出"我具体做了什么"。
> 所有"主导""推动""智能""真实"——要么有据可查，要么砍掉。

## 2. 新东方 · Signals — 4 个主 bullet

**当前 bullet 2：**

**浮夸点：**
- "真实 bad case" → "真实"删掉。bad case 本来就是真的。

**建议：** "每层由 bad case 驱动" 即可。

---

**当前 bullet 4：**
> NSGA-III 多目标选校优化 + Sobol QMC 蒙特卡罗相关性模拟：自动生成 3 套最优申请方案（冲/稳/保 30/40/30），附带 AI 定制 PDF 报告（reportlab，中文水印 + 学校 Logo + 雷达图）

**浮夸点：**

**需要你确认：** PDF 报告里的文字是 LLM 写的还是模板？如果是 LLM → "LLM 生成"; 如果是模板 → "自动生成"。
**建议：** "最优"→"多套"或直接"冲/稳/保三档"。

## 3. 新东方 · 其他工作 — RAG 那行

**当前：**
> RAG 知识库：多语言 Embedding + GNN 图重排 + Tesseract OCR，支持 20+ 文档格式，提取准确率 >85%，减少 70% 人工校验

**浮夸点：**
- 一句话塞了 6 个信息点，密度太高，读的人喘不过气
- "Tesseract OCR" 和 "20+ 文档格式" 是操作细节，不传递能力信号

**建议：**
> RAG 知识库：多语言 Embedding + GNN 重排，提取准确率 >85%，减少 70% 人工校验

砍掉 Tesseract 和 20+ 格式。剩下 4 个信息点——Embedding（模型能力）、GNN重排（图算法能力）、>85%（效果）、-70%（效率）——每个都传递不同维度的信号。

## 4. 字节跳动 — 3 个 bullet

**当前 bullet 1：**
> **主导**泛化召回 Badcase 归因体系，**推动**模型标注策略迭代，泛化召回率 +8.2%，准确率 +3.8%

**浮夸点：**
- "主导" — 你当时是搜索运营，不是归因体系的 owner。如果面试官追问"你怎么主导的？你下面带人了吗？"，答不上来就穿帮。
- "推动模型标注策略迭代" — "推动"在字节语境里通常意味着跨团队 push——你当时推了哪个团队？具体做了什么？

**需要你确认：** 你在 Badcase 归因这件事上到底是什么角色？
- 如果是你一个人设计+执行 → 用"负责"
- 如果是你分析完给建议、别人落地 → 用"参与"或直接陈述事实
- 如果是你分析 badcase 然后产出标注优化方案 → 直接写"Badcase 归因与标注优化"

**建议（中性版）：**
> 负责泛化召回 Badcase 归因与模型标注优化，泛化召回率 +8.2%，准确率 +3.8%

删"主导""推动"，动词降级，让数字自己说话。

---

**当前 bullet 2：**
> 设计泛化收益指标体系 + AB 实验指标，搭建多层粒度自动化归因看板，解决异常波动定位难点

**浮夸点：**
- "解决异常波动定位难点" — 有点大词。"难点"是什么？如果你一个人解决了，你是怎么解决的？

**建议：**
> 设计泛化收益指标体系与 AB 实验指标，搭建多层粒度归因看板，定位异常波动根因

"解决…难点"→"定位…根因"。陈述你做了什么，不陈述你"解决了什么难题"。

---

**当前 bullet 3：**

**这个 bullet 没浮夸。** "独立负责"有据可查（你是卡片的产品 owner），"+2%"是 Libra 面板上的数字。保留不动。

原本考虑加一行"Python · XGBoost · Scikit-learn · Streamlit · FastAPI · SQL · Spark · DeepSeek API · ReportLab · PaddleOCR"给 ATS 吃。

**决定不加。** 原因：
- 每个关键词已经在工作经验的 bullet 里自然出现了（XGBoost 在 bullet 1，LLM Agent 在 bullet 3，ReportLab 在 bullet 4，PaddleOCR 在项目节……）

- ATS 解析工作经验的 bullet 正文同样能命中关键词

## 8. 每改一步的检查标准

改完每一行，问自己三个问题：
1. 面试官追问"你怎么做的"，我能展开 3 分钟吗？
2. 这句话去掉任何一个词，意思还完整吗？（如果还完整，那个词就是浮夸）
3. 如果我面的是字节 DS 面试官，这句话会不会让他觉得我在包装？
