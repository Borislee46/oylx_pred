## 3. 数据结构

### 3.1 predictions.json 顶层

```json
{
  "meta": {"created": "2026-05-09", "owner": "李佳鹏", "birth": "1993-04-06 子时"},
  "predictions": []
}
```

### 3.2 预测对象完整字段

```json
{
  "id": "p2026_019",
  "created": "2026-05-13",
  "prediction": "具体、可证伪的预测文本",
  "category": "career",
  "confidence": "中",
  "combined_confidence": "中",
  "bazi_signals": [
    {"source": "大运·壬子", "signal": "偏财坐正财", "direction": "吉/凶/平", "reason": "..."}
  ],
  "ziwei_signals": [
    {"source": "流年命宫", "signal": "天同化禄", "direction": "吉", "reason": "..."}
  ],
  "cross_check": "一致 / 部分分歧 / 完全相悖 / 仅紫微 / 仅八字 / 待交叉验证",
  "tags": [],
  "window": {"start": "2026-01-01", "end": "2026-12-31"},
  "status": "pending",
  "verification": null
}
```

**ID 生成**：读 predictions 数组 → 最大序号 → `p{年份}_{max+1:03d}`

**字段说明**：
- `confidence`: 原始单体系置信度（向后兼容）
- `combined_confidence`: 两层交叉后的综合置信度
- `cross_check`: 两体系信号一致性标记
- `bazi_signals` / `ziwei_signals`: 各自信号数组，互不替代

### 3.3 验证对象

```json
{
  "date": "YYYY-MM-DD",
  "outcome": "实际可观测结果",
  "match_level": "吻合 / 部分吻合 / 不吻合 / 暂无证据",
  "adverse_evidence": "",
  "is_post_hoc": false,
  "intervention_applied": false,
  "temporal_precision": "窗口内 / 相邻月 / 隔季 / 跨年"
}
```

**状态转换**：吻合/部分吻合 → verified | 不吻合 → missed | 暂无证据 → 不变

## 4. 操作模板

### 4.1 新增预测

**触发词**：`记一条预测` `新预测`

**流程**：读 predictions.json → 确认预测内容/类别/应期 → 生成ID → 写入 → 回复确认

**写入前检查**：预测是否具体可证伪？应期是否有明确结束日？两体系信号是否都填写了？

### 4.2 验证预测

**触发词**：`验证 p2026_XXX` `这条应验了` `这条没应验`

**流程**：读 predictions.json → 找目标 → 收集 outcome/match_level/adverse_evidence → 更新 status → 写回

### 4.3 查看/筛选预测

**触发词**：`看 p2026_XXX` `有哪些等着验证的` `感情类预测` `全部预测`

**流程**：读 JSON → 按条件过滤 → 展示

### 4.4 统计报告

**触发词**：`统计报告` `准确率`

**流程**：简单统计 Claude 直接读 JSON 算；复杂统计运行 `python predictions/stats.py --json`

### 4.5 八字查询

**触发词**：`看看八字大运` `现在走什么大运`

→ 读 `data/八字命盘_1993年4月6日.json` → dayun 段 → 定位当前大运 → 返回干支十神+区间

**触发词**：`看看八字格局` `身强身弱`

→ 读八字JSON → pattern/strength/tiaohou 段 → 展示

### 4.6 紫微查询（原有）

**触发词**：`命宫怎么说` `夫妻宫如何` `流年四化`

→ 读紫微JSON + 完整版分析文档 → 展示

### 4.7 两层综合解读（默认模式）

**触发词**：`看看2026年运势` `今年运势如何`

**流程**：
1. 读八字JSON → 当前大运 + 流年 → 八字底色（大运波段+年度气质）
2. 读紫微JSON → 流年宫位+四化 → 紫微前景（具体事件信号）
3. 两层叠加呈现：底色在前，前景在后
4. 相悖标注"两体系分歧"，一致标注"两体系一致"
5. 每个结论标注来源：[八字·大运]、[八字·流年]、[紫微·流年X宫]

## 5. 分析铁律

### 5.1 推理标注出处
每条结论引用命盘JSON字段或分析文档章节。禁止无出处的模糊断言。

### 5.2 列出多种可能
同一星曜/十神组合 → 至少2种现实对应 → 标注哪种在当前背景下更可能。

### 5.3 不逢迎
命盘有就说，没有就说没有。信息不足就说"信息不足"。禁止选择性汇报。

### 5.4 风险+缓解
推到行动建议时：风险按概率排序 → 附缓解措施 → 指明通过条件。禁止"命中注定"。

### 5.5 What-If 对比
每条行动建议：不做的最坏情况 vs 失败的最坏情况 → 诚实比较。

## 6. 两层分析铁律（八字 + 紫微）

| 维度 | 八字 | 紫微 |
|------|------|------|
| 大运/大限（10年波段） | **主** | 辅 |
| 流年（年度） | 底色 | **主**（事件触发） |
| 具体事件/时机 | 背景约束 | **主**（精准定位） |
| 格局/体质 | **主** | 辅 |

**规则**：
1. 任何运势分析必须两层同框，不可只给单侧
2. 信号一致 → 标注"两体系一致"，置信度+1级
3. 信号互斥 → 标注"两体系分歧"，分别列出，不强行统一
4. 仅一体系有信号 → 标注"仅X体系有信号"
5. 每个结论标注来源：[八字·大运X]、[八字·流年X]、[紫微·流年X宫]
