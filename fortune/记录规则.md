# 记录规则

> 本文件定义事实日志和命理对照本的记录规范。
> 目的：保证记录客观、可验证、不自洽圆谎。
> **AI 交互层面**：Claude 的具体操作流程（何时读哪个文件、JSON 字段怎么填、状态怎么转换）见 [`SKILL.md`](SKILL.md) — 该文件定义操作模板和验证检查清单。本文件定义的是"为什么"和"怎么判断"，SKILL.md 定义的是"怎么做"。

---

## 一、事实日志规则

### 1.1 可记录的内容

只有同时满足以下条件才能写入事实日志：
- **有具体时间**（精确到月；关键事件精确到日）
- **有具体行为或可观测结果**（不是感受，是你做了什么 / 发生了什么）
- **可以事后被第三方核对**（聊天记录、邮件、offer、合同、照片等）

### 1.2 不可记录的内容

- 纯粹的"感觉"（如"我觉得命运动了"）——感受必须绑定具体事件
- 命理解释（如"这是因为贪狼忌"）——那是命理对照本的事
- 对他人动机的推测（如"他可能在排挤我"）——只能记录可观测行为
- 模糊的未来预测（如"明年可能会换工作"）

### 1.3 感受记录的正确写法

**错误**：`最近很累`
**正确**：`2026.05.09 记录：4月起每日有效个人时间 < 2 小时。身体信号：入睡困难，早晨不愿起床。`

感受必须附在可观测事实后面，不单独成条。

### 1.4 修改规则

- 过去的事件**只能追加，不能修改**（写错了可以补一条更正，但不能改原条目）
- 每次记录标注记录日期（可能晚于事件日期）
- 如果后来发现某条记录的事实有误，新开一条 `更正：` 条目，保留原始记录

## 二、命理对照本规则

### 2.1 对照结构

每条对照必须包含四个字段：

| 命盘信号（来源） | 现实事件（证据） | 吻合度 | 不利证据 |
|------|------|------|------|
| 来自JSON的具体星曜/四化 | 具体时间+行为 | 吻合/部分/不吻合/暂无证据 | 如果命盘预测X但实际发生了非X |

**不允许**只有"命盘信号"和"现实事件"两列——那会让对照变成单向验证。

### 2.2 不利证据强制记录

以下几种情况必须写入"不利证据"列：
- 命盘某星曜组合的常见解释与实际不符
- 某大限预测的"典型表现"未出现
- 四化应期已过但未发生

例：命盘显示"廉贞忌入子女 → 血光/炎症/感情执念"，如果2026年结束后未出现任何血光或炎症事件，必须记录为"廉贞忌血光预警：已过应期，未发生"。

### 2.3 禁止事后合理化

事件发生后才匹配命盘的，必须标注为`事后匹配`。事件发生前命盘已预测的，标注为`事前预测`。两者权重不同。事后匹配不能算作验证。

### 2.4 对照数据来源

所有命盘信号必须引用 `命盘数据_1993年4月6日.json` 中的具体字段，格式：
`JSON: palaces[4].stars.main[0] = 天同[平]`

### 2.5 八字信号来源

八字对照与紫微平行，信号取自 `data/八字命盘_1993年4月6日.json`：

| 信号来源 | JSON路径 | 说明 |
|---------|---------|------|
| 四柱十神 | pillars.{year/month/day/hour}.shishen | 原局十神配置 |
| 大运干支 | dayun.periods[N] | 当前十年大运，干支+十神 |
| 流年干支 | liunian.{year} | 当年流年，干支+十神 |
| 格局 | pattern | 格局名+用神忌神 |
| 身强弱 | strength | 身强/身弱+得分 |
| 调候 | tiaohou | 调候用神 |
| 地支关系 | branch_relations | 合冲刑害破 |
| 神煞 | shensha | 贵人驿马桃花等 |

### 2.6 两层交叉验证

每次对照须同时检查八字和紫微两体系：

- 事件发生 → 先看八字大运+流年是否提供背景条件 → 再看紫微流年宫位+四化是否提供触发
- 两体系一致 → 标注"两体系一致"，增强置信度
- 两体系分歧 → 标注"两体系分歧"，分别记录各自信号
- 仅一体系有信号 → 标注"仅八字有信号"或"仅紫微有信号"

## 三、两份文档的分工

```
你经历了一件事
    │
    ├─ 事实是什么？ → 事实日志（只记不解释）
    │
    └─ 命盘怎么说的？吻合吗？→ 命理对照本（对照验证）
```

事实日志是**真相源**。如果命理对照本的解释和事实日志冲突，相信事实日志。

---

## 四、每次记录的检查清单

记录前自问：

1. 这是可观测的事实，还是我的感受/推测？如果是后者，附在事实后面，不单独成条。
2. 有没有命理解释混进了事实描述？如果有，移到对照本。
3. 如果是写入对照本，有没有填"不利证据"列？
4. 我有没有因为想让命盘"应验"而扭曲事实？如果有，重写。
5. 如果是过去事件的回顾，有没有标注"事后匹配"？

## 五、月度行动清单规则

### 5.1 文件命名与位置

- 存放路径：`monthly/actions/YYYY-MM.md`
- 例：`monthly/actions/2026-05.md`

### 5.2 生命周期

```
月初：创建当月行动清单
    │
    ├─ 月中：持续更新完成状态
    │
月底最后一天：必须做月末回顾
    │  ├─ 逐条标注：完成 / 未完成（写原因，不写借口）
    │  └─ 未完成项：决定是迁移到下月还是放弃
    │
归档：回顾写完后，移动到 monthly/actions/archive/
```

### 5.3 月末回顾格式

每条行动必须标注实际结果：

```
## 月末回顾（2026-05-31）

### 完成
- [x] 推汇报给yzq — 5月12日完成，反馈正面

### 未完成
- [ ] 每天2h物理隔离LX — 实际平均1h，因为项目赶工。迁移至6月。
- [ ] 晚11点后不碰手机 — 放弃。不可执行，改为"床头不放充电器"。
```

### 5.4 跨月迁移规则

- 未完成项迁移到新清单时必须注明原创建月份
- 同一项迁移超过2次（连续3个月未完成）→ 标记为「需重新设计」，暂停迁移，重新评估可行性
- 不允许"永久进行中"的项目——每个行动必须有截止条件

*规则生效日期：2026.05.09*

## 六、命理分析交互规则

> 本节约束 Claude 在 fortune 系统内的行为方式。目的：保证分析严谨、客观、可证伪。
> **操作层面**：本节定义的是推理的"质"（如何分析、如何画分支、如何控制语言）。具体的操作流程（何时读哪个文件、JSON 字段怎么填、状态怎么转换）见 [`SKILL.md §4-§6`](SKILL.md)。两条线互为表里——铁律管推理质量，SKILL.md 管执行步骤。

### 6.1 推理必须标注来源出处

一切命理推理必须标注出处。不允许凭空猜测或泛泛而谈。

出处格式要求：

- **命盘数据引用**：`JSON: palaces[X].stars.main` 或 `JSON: liuNianData[2026].siHua[0]`
- **文档引用**：`完整版 §十二·迁移宫` 或 `风水分析 八`
- **流派引用**：`三合派·星性论` `飞星四化·宫位互涉` `钦天门·斗数秘仪`

**违规示例**：
- `你的夫妻宫不好` （没说出处）
- `今年有变动` （没说是哪个四化、哪个宫位）

**正确示例**：
- `夫妻宫（寅）空宫+大耗+劫煞，四化空转（JSON: palaces[2].stars.main = []），夫妻宫体质偏弱——这是命盘结构性的，不是流年才有。`

### 6.2 指出多种可能性

命盘信号 → 现实事件的映射不是一对一的。同一个星曜组合，现实中可能有几种完全不同的体现方式。

分析时要求：

- 对每个命盘信号，列出至少 **2 种**可能的现实对应
- 标注哪种在当前背景下更可能
- 举例要具体，不抽象

**示例**：

> 廉贞七杀擎羊同宫子女宫，常见的现实对应：
> 1. **血光/手术**（廉贞血光+七杀刀+擎羊刃，最直读）
> 2. **感情执念**（廉贞化忌，子女宫管桃花，执念不放手）
> 3. **意外伤害/车祸**（七杀擎羊冲照迁移宫时）
> 4. **快速决策型人格**（七杀擎羊 = 果断到有点冲动）
>
> 对你来说，2026廉贞忌入子女 + 夫妻宫大限最后一年，第2种（感情执念）可能性最高。

**另一个例子**：

> "二婚"这个名字容易误导。现实中可以是：
> 1. 拿了结婚证立马离了再领——法律上算二婚
> 2. 长期同居后分手，再正式结婚——大部分人理解的二婚
> 3. 一段关系实际破裂后又复合——命盘上看像二婚，法律上不是
>
> 说"二婚"的时候必须说清楚是哪种。

### 6.3 不逢迎，有一说一

这是最核心的一条。命盘里有的就是有，没有的就是没有。**禁止为了让命主心情好而选择性汇报**。

具体要求：

- 吉星组合 → 说吉，不夸大
- 凶星组合 → 说凶，不粉饰
- 空宫/信息不足 → 说"信息不足，不强行解读"
- 命盘没有依据但你希望是真的 → **不说**

**检查清单**（每次分析后自问）：

1. 我有没有因为觉得命主想听，就强调了好的部分？
2. 我有没有因为怕命主焦虑，就淡化了一个明确的凶信号？
3. 命盘的依据够强吗？如果不够，我有没有如实说"这个推断的确定性不高"？

> 命理分析的目标不是安慰剂。安慰剂让人感觉好但不解决问题。
> 目标是：让命主看到全貌，然后做出更清醒的决策。

### 6.4 落地时多想风险，但不制造过度焦虑

命理分析最终要落地到"怎么办"。这个环节的平衡最难。

**风险分析要求**：

- 推到行动建议时，必须先列风险清单
- 风险按概率排序：高概率/中概率/低概率
- 每个风险必须给出具体的缓解措施

**焦虑控制要求**：

- 区分：这是"可能发生"还是"大概率发生"
- 如果命盘信号确实凶，给它一个**真实的时间窗口和通过条件**，而不只是一个吓人的标签
- 禁止使用"命中注定""躲不过"这类封闭式语言——就算凶星来，也可以预备、可以稀释、可以通关

**示例（正确平衡）**：

```
2026.06 ⚠️ 贪狼忌 + 廉贞忌交会夫妻宫
    │
    ├─ 大概率：感情敏感期，容易因为小事放大情绪
    │   缓解：6月不做感情决策，等7月贪狼忌过后再谈
    │
    ├─ 中概率：旧情复燃 / 第三方介入
    │   缓解：主动保持物理距离，减小接触面积
    │
    └─ 低概率：关系破裂
        即使发生→不是终点。35岁大限切换后夫妻宫格局变化，窗口重新打开。
        通过条件：一次不崩算通关。
```

> 核心原则：**告知真实风险 + 给出可执行的缓解措施 + 指明通过条件 = 赋能。**
> 只说风险不说缓解措施 = 传播焦虑。

### 6.5 What-If 反事实推演：不做会怎样，失败了会怎样

人的默认偏差是**只分析行动的风险，不分析不行动的风险**。做了可能失败 → 害怕 → 不做。但不做的代价往往更大——只是它不直观，不触发损失厌恶，所以被忽略。

本规则要求在给出每条行动建议时，必须同时运行两个 what-if 分支：

#### 分支 A：如果我不做

```
现状基线 → 如果什么都不改变，N 个月后最可能发生什么？
```

要求：
- 不能写"维持现状"——没有真正的静止，不进则退
- 必须引用命盘中的时间窗口（大限切换、流年四化过期不候）
- 标注**不作为的隐性成本**：机会窗口关闭、惯性累积、他人先行

#### 分支 B：如果我做了但失败了

```
尝试了 → 最坏结果是什么 → 这个最坏结果，比"不做"的结果更差吗？
```

要求：
- 区分"可逆损失"和"不可逆损失"——大多数失败是可逆的
- 如果失败了，命盘中还有没有第二次机会（如下一个大限、下一轮四化）
- 标注**失败的残值**：失败了能留下什么（技能、关系、信息、信用）

#### 输出格式

每个行动建议必须带以下三行对比：

```
不做的最坏情况：  [N个月后具体会发生什么，引命盘时间窗口]
失败的最坏情况：  [尝试后最坏结果 + 可逆/不可逆标注]
为什么失败更优（或更差）：[一句话比较，可以诚实地说"不做更好"]
```

**诚实条款**：如果推演结果是"不做更好"，必须如实说。这条规则的目的不是强迫行动，而是打破"默认不做"的惯性——但破完之后，结论可能是做，也可能是不做。

**示例**：

```
行动建议：2026.12 前推汇报给 yzq，争取第四大限开局话语权

不做的最坏情况： 2027立春大限切换后，天机权入官禄的时间窗口仍在，但 yzq 对你的认知
                 已固定在"执行层"标签上（大限切换不等人，人事印象有惯性）。
                 重新建立认知的成本 ×3~5。
                 命盘依据：官禄宫天机太阴科（JSON: palaces[8]）— 窗口在但不等你。

失败的最坏情况： yzq 不认可，回到原位。可逆损失——技能和方案留在手上，
                 可以在外部验证（跳槽/面试）。残值：一次完整的向 CEO 汇报的复盘经验。
                 命盘依据：迁移宫巨门权+文昌科（JSON: palaces[6]）— 外部通道同时存在。

为什么失败更优： 不做 → 窗口过期 + 认知固化（不可逆）。
                 失败 → 技能可带走 + 外部有备份通道（可逆）。
```

**启发式检查**（每次给出建议后自问）：

1. 我有没有画"不做的最坏情况"？还是只画了"做的风险"？
2. 失败的损失是可逆的还是不可逆的？如果是可逆的，我有没有说清楚恢复路径？
3. 有没有命盘依据说明"机会只有一次"还是"还有下一班车"？

*规则生效日期：2026.05.10*

## 七、方法论基础：贝叶斯推断框架

> 本节解释这个系统**为什么能产生知识**，而非只是"记录"。

### 7.1 核心框架

本系统的认识论基础是将命理推演视为一个**贝叶斯更新过程**：

```
P(命盘解释为真 | 观测到的事件) ∝ P(观测到的事件 | 命盘解释为真) × P(命盘解释为真)

后验概率                ∝ 似然                        × 先验概率
```

三个层次对应系统的三个组件：

| 贝叶斯项 | 系统对应 | 来源 |
|---------|---------|------|
| **先验 P(H)** | 命盘信号 → 某宫位/星曜组合 → 典型现实表现的范围和概率 | `命盘数据.json` + 紫微斗数各流派积累的星性论 |
| **似然 P(D\|H)** | 该信号在命主过往经历中被验证/证伪的程度 | `事实日志.md` + `命理对照本.md` |
| **后验 P(H\|D)** | 更新后的信号可靠性评估（升级/降级/细化） | `predictions.json` 验证结果 + `stats.py` 统计 |

### 7.2 为什么传统算命不可证伪，而这里可以

传统命理话术的结构：

> "你交友宫有忌，注意人际关系。"

这句话的问题：
- 没有具体预测 → 无法验证
- 没有时间窗口 → 永远不失效
- "人际关系"涵盖一切 → 任何事情都可以事后解释为"你看，这就是人际关系问题"
- **不可证伪的陈述不产生信息。**

本系统的改造——每条命盘信号必须满足：

1. **具体化**：不是"注意人际关系"，而是"内推渠道失败的概率高于正式招聘"
2. **设应期**：不是"某天会出事"，而是 `2027-02-03 ~ 2027-12-31`
3. **定义通关条件**：不是"命里有此一劫"，而是"拿到 offer → 应验；没拿到 → 未应验"
4. **记录不利证据**：命盘预测了 X 但实际没发生 → 必须写入，不能跳过

**这四个条件将命理陈述从不可证伪的模糊断言，转化为可验证的概率预测。**

### 7.3 贝叶斯更新的一次完整实例

以 p2026_018 风险②的更新过程为例：

**先验（2026.05.10 初始录入）**：

> P(贪狼忌在交友宫 → 朋友帮忙反而翻车 | 命理先验) ≈ 中等偏高
>
> 来源：紫微斗数星性论——贪狼忌在交友宫 = 人际合作易生变数

**似然（同日，调取事实日志）**：

> P(2024年两次字节面试均走mjh内推且均失败 | 贪狼忌交友宫为真) ≈ 高
>
> 来源：事实日志——可观测的、有具体时间的、记载了渠道和结果的两次失败

**后验更新**：

> P(贪狼忌交友宫 → 内推翻车 | 数据) ↑ 显著上升
>
> 风险从"理论推断"升级为"已实证"。预测内容改写：明确标注"2024年两次均走mjh内推渠道，均失败。命盘交友宫贪狼忌的核心含义在此得到直接验证。"

这次更新的本质是：**用一个真实数据点，把模糊的先验收窄为一条具体的、可操作的规则——2027年走官方渠道，不走内推。**

### 7.4 系统的校准方向

随着验证数据积累，系统将逐步回答以下问题：

| 问题 | 当前状态 | 需要的数据 |
|------|---------|-----------|
| 哪个宫位的预测最准？ | stats.py 已按宫位统计应验率，但 N 太小 | ≥ 50 条已验证预测 |
| 哪个宫位是盲区？ | stats.py 已支持盲区检测（`--json` 输出含 coverage） | — |
| 按置信度分层的应验率？ | stats.py 已支持按 confidence 分组统计，N 太小 | ≥ 30 条已验证预测 |
| 哪个流派的解释框架更可靠？ | 三合/飞星/河洛/钦天混合使用 | 按流派标签分组的验证数据 |
| "事前预测"和"事后匹配"的应验率差多少？ | stats.py 已区分，事后匹配的"应验率"天然虚高 | 保持记录来源标签 |
| 命盘信号强度如何影响预测精度？ | 未量化 | 为每条预测标注信号强度（强/中/弱），交叉验证 |
| 观测者效应有多强？ | verification 已支持 intervention_applied 字段 | ≥ 10 条标记了 intervention_applied 的预测 |
| 时间精度分布？ | verification 已支持 temporal_precision 字段（窗口内/相邻月/隔季/跨年） | ≥ 20 条已验证预测 |

### 7.5 系统的边界

必须诚实说明这个框架的局限：

1. **小样本问题**：当前 18 条预测、0 条已验证。统计上，任何基于此的"准确率"都没有意义。需要持续积累。
2. **选择偏差**：命主倾向于记录自己关注领域的预测（事业、感情居多），覆盖不均匀。
3. **观测者效应**：预测本身可能改变行为（如 p2026_016 红线守则让你刻意回避某些场景），从而影响结果——这与"观测者独立"的统计假设冲突。这不是 bug，是特性——命理分析的目标本就是影响决策，但统计验证时需要考虑这个效应。
4. **先验来源的可靠性**：紫微斗数星性论本身是几百年经验归纳，不是从公理推导出来的。本系统不试图证明星性论为真——它只验证：**当星性论给出一个具体预测时，这个预测在命主身上的命中率是多少。** 这是可测量的。

### 7.6 与机器学习的类比

这个系统的架构可以映射到标准 ML pipeline：

```
命盘 JSON          →  特征工程（feature store）
命盘分析文档        →  特征重要性 + 领域知识（feature importance / expert rules）
predictions.json  →  标注数据集（labeled dataset）
事实日志            →  真实标签（ground truth）
record.py verify  →  模型评估（evaluation）
stats.py          →  性能报告（metrics dashboard）
记录规则.md        →  ML 实验规范（experiment protocol）
```

> 核心区别只有一个：ML 模型从数据中自动学习特征权重；这个系统的特征权重是命理先验给的，数据的作用是**修正先验**。这更接近贝叶斯统计建模，而非频率学派的端到端训练。
